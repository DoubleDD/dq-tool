# 表标记与统计 — 实施计划(实施结果记录)

> 状态:已完成
> 需求来源:`docs/requirements/表标记与统计需求.md`(2026-08-06 确认)

## 一、概述

在 dq-tool 中落地「表标记」能力:全局共享的表级标记(粒度 = 数据源 + 库 + 表名,一表多标记),
系统「空表」标记由扫描结果自动驱动,用户标记在打标弹窗内集中管理(新建/改名/改色/删除);
两个统计视图:库维度(库列表页标签块 + 点击筛选)与标记维度(独立统计页)。
分层遵循项目约定:业务逻辑全部在 common 模块(Kotlin),server 只加 Javalin 薄壳路由,前端 Vue 页面消费 REST 接口。

## 二、数据模型(V3 迁移)

`common/src/main/resources/db/migration/V3__tag.sql`(Flyway,新库/老库均生效):

- `tag_def`:标记定义,`name` 全局唯一(唯一索引),`color` 默认 `#409EFF`,`kind` 区分 USER / EMPTY
- `table_tag`:打标关系,唯一键 `(tag_id, datasource_id, db_name, schema_name, table_name)`,
  `tag_id` 外键 `ON DELETE CASCADE` —— 删除标记自动解除全部打标关系,无残留;
  `db_name` 空串兜底(无库概念的方言存空串保证唯一键,口径与 `table_doc` 一致)
- 系统「空表」标记按名称幂等 `MERGE INTO` 插入(`#909399`,kind=EMPTY),老库升级同样生效

## 三、内核设计(common 模块)

- `model/Tag.kt`:`Tag(id, name, color, kind, tableCount)` + `TagKind` 枚举(USER/EMPTY)
- `model/TagStats.kt`:`TagStats`(标记维度统计)/ `TagSchemaStat`(库分布行)/ `SchemaTagStat` + `SchemaTagCount`(库维度计数)
- `repository/TagRepository.kt`:标记 CRUD、打标关系整体替换、库维度计数、标记库分布(行/列只取最近一次 DONE 的 scan_table 快照)等 SQL
- `service/TagService.kt`:校验与组装 —— 重名抛 `IllegalStateException`(web 映射 409),操作空表标记/参数错抛
  `IllegalArgumentException`(400);`replaceTableTags` 整体替换单表 USER 标记(空表标记不可手动打摘)
- **空表联动点**:`scan/ChunkRunner.kt` 的 `finalizeTable` —— 表 DONE 后调用 `TagService.syncEmptyTag`,
  行数为 0 确保打上「空表」、非空摘除(幂等);联动失败只记 warn,不影响扫描结果

## 四、API 清单(server 层)

`server/src/main/java/com/example/dq/controller/TagController.java`(路由注册于 `web/WebServer.java`,全部在 `/api/*` 下自动受授权拦截):

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/tags` | 全部标记(含「空表」),带打标表数 → `Tag[]` |
| POST | `/api/tags` | 新建 `{name, color}` → `Tag` |
| PUT | `/api/tags/{id}` | 改名/改色 `{name, color}` → `Tag` |
| DELETE | `/api/tags/{id}` | 删除(打标关系级联解除)→ 200 |
| GET | `/api/tags/{id}/stats` | 标记维度统计 → `TagStats` |
| GET | `/api/datasources/{dsId}/schema-tag-stats?db=` | 库维度标记计数 → `SchemaTagStat[]` |
| GET | `/api/datasources/{dsId}/schemas/{schema}/table-tags?db=` | 整库 表名→`Tag[]` map |
| PUT | `/api/datasources/{dsId}/schemas/{schema}/tables/{table}/tags?db=` | 整体替换单表 USER 标记 `{tagIds:[...]}` → 该表最新 `Tag[]` |

`db` query 参数原样透传,内核归一为空串;`kind` 序列化为 `"USER"/"EMPTY"`(Jackson 3 + KotlinModule)。

## 五、前端落点

- `web/src/components/TableTagDialog.vue`:表列表「打标」弹窗 —— 勾选当前表标记(只列 USER)+ 标记集中管理(新建/改名/改色/删除)
- `web/src/views/Tables.vue`:新增「标记」列;路由 query 带 `tagId` 时进入按标记筛选的只读模式(隐藏操作列/选择列)
- `web/src/views/Schemas.vue`:库行新增标记标签块(色点 + 名称 + 数量,超过 3 个折叠「+N 更多」),点击跳只读表列表
- `web/src/views/TagStats.vue`:标记统计页(路由 `/tags`,页签「标记统计」)—— 左侧标记列表,右侧指标卡 + 按库分布表(可排序、合计行),数字点击跳只读表列表

## 六、统计口径

- 表数为打标关系计数,不依赖扫描;行数/列数只累计最近一次 DONE 扫描快照
- 未扫描过的表:行/列显示「—」,不计入累计(库内全部未扫描时该库合计为 null → 「—」)
- 多标记重复计入:一张表在每个标记的统计中各 +1;`TagStats.coveredTables` 为跨标记去重的实际打标表数,仅展示
- 库维度计数只返回有标记表的库(空库不出标签块)

## 七、测试

- common:`TagServiceTest`(重名 409/空表标记保护/统计组装/空表联动幂等)、`TagRepositoryTest`(级联删除、库维度计数)
- server:`WebServerSmokeTest` 扩展 —— 标记列表含系统「空表」、POST→PUT→DELETE 生命周期、单表打标与整库查询往返、两个统计端点空数据可达、重名 409(授权用测试临时 Ed25519 密钥对签发永久授权码激活)

## 八、手动验证清单

1. `make dev` + `cd web && npm run dev` 启动(或 `make build && make run`)
2. 激活授权后建数据源,进入库列表选库扫描一批表
3. 扫描完成后:行数为 0 的表在表列表「标记」列自动出现「空表」;非空表无
4. 表列表点「打标」:弹窗内新建标记(选颜色)、勾选/取消、改名、改色、删除;重名给出 409 提示;空表标记不出现在可选列表
5. 库列表页:库行出现标记标签块,超过 3 个折叠「+N 更多」;点击标签块跳只读表列表(顶部提示筛选中,操作类交互隐藏)
6. 「标记统计」页签:左侧列表点选标记,右侧指标卡(总表数/总行数/总列数/覆盖表数)与按库分布表正确;未扫描库行数显示「—」;点分布数字跳只读表列表
7. 再次扫描把空表灌数据后,「空表」标记自动摘除
