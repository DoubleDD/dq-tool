# 错误收集系统（错误中心）实施计划

> 需求：现有「系统诊断」只有一段内存日志摘录、「运行日志」只有 SSE 实时流，真正的运行时错误
> （前端 JS 报错、后端业务异常、数据库错误、后台任务异常、启动异常）大量收不到、重启即失、无法检索。
> 目标：**任何一个地方产生的异常都统一采集、落库、可查可筛可标记**。

## 一、现状与缺口

| 位置 | 现状 | 缺口 |
|---|---|---|
| 后端日志 | `logback.xml` 文件滚动 + `LogStreamAppender` 内存环形缓冲 500 条 | 内存态，重启即失；只按条存，无聚合/无检索/无状态 |
| 后端异常映射 | `WebServer` 各分支 `log.warn/error` | 已落日志，但落不进可检索的错误库 |
| 后端业务 catch | `common` 内约 20 处 `catch` 静默吞掉 | 真正的逻辑错误既无日志也无处可查 |
| 后台任务 | `scan_job.error` / `report_export.error` 等各自落表 | 分散在各业务表，没有统一入口 |
| 未捕获线程异常 | `DqApplication` 只写 `startup.log` | 进不了错误库，也不进 logback |
| 前端 | 只有 `router.onError` 处理 chunk 失败 | 无 `window.onerror` / `unhandledrejection` / Vue `errorHandler` / 接口错误上报 |

## 二、总体设计

```
前端                                    后端
┌──────────────────────┐   POST /api/errors/report   ┌─────────────────────────────┐
│ errorCapture.js      │ ──────────────────────────► │ ErrorCenterController       │
│  window.onerror      │                             │        │                    │
│  unhandledrejection  │                             │        ▼                    │
│  Vue errorHandler    │                             │ ErrorCenterService(common)  │
│  console.error 补丁  │                             │  · 指纹归一 + 聚合(occurrences)│
│  axios 拦截器 4xx/5xx │                             │  · 异步单写线程 + 有界队列     │
└──────────────────────┘                             │  · 启动期磁盘 spool 兜底      │
                                                     │        ▲                    │
┌──────────────────────┐   Logback event             │        │ ErrorSink          │
│ DqApplication        │ ──────────────────────────► │ ErrorCaptureAppender(server)│
│  未捕获线程异常       │                             │  · ERROR 全收                │
│  ErrorCenter.report  │                             │  · WARN 且带 throwable 才收   │
└──────────────────────┘                             │  · SQLException → DATABASE   │
                                                     └─────────────────────────────┘
                                                                  │
                                                       H2 error_record（指纹唯一）
                                                                  │
                                                       /errors 错误中心页面
```

关键决策（用户已确认）：

1. **入口**：新增独立页面 `/errors`，复用「系统诊断」菜单 key 与「放行激活检查」口径（老授权码升级即可见，无需重签）。
2. **前端范围**：JS 运行时错误 + 未捕获 Promise + Vue 组件错误 + `console.error` + 接口 4xx/5xx/网络错误。
3. **存储**：落 H2，按指纹聚合计数，默认保留 30 天，可标记已处理/已忽略。

## 三、数据模型

新增迁移 `common/src/main/resources/db/migration/V56__error_record.sql`（已发布迁移不得修改）：

```sql
CREATE TABLE IF NOT EXISTS error_record (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    fingerprint   VARCHAR(64)  NOT NULL,          -- SHA-256(source|kind|归一消息|首帧)
    source        VARCHAR(16)  NOT NULL,          -- BACKEND/FRONTEND/DATABASE/TASK/STARTUP
    kind          VARCHAR(128) NOT NULL,          -- 异常类名 / JS 错误类型 / API_ERROR
    level         VARCHAR(8)   NOT NULL,          -- WARN/ERROR/FATAL
    message       VARCHAR(2000),
    detail        CLOB,                           -- 最近一次完整堆栈
    context       CLOB,                           -- 最近一次上下文(路由/接口/浏览器/参数)
    logger        VARCHAR(255),
    thread        VARCHAR(160),
    route         VARCHAR(512),
    occurrences   INT NOT NULL DEFAULT 1,
    first_seen    TIMESTAMP NOT NULL,
    last_seen     TIMESTAMP NOT NULL,
    app_version   VARCHAR(32),
    status        VARCHAR(16) NOT NULL DEFAULT 'OPEN',   -- OPEN/RESOLVED/IGNORED
    note          VARCHAR(2000)
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_error_record_fp ON error_record(fingerprint);
CREATE INDEX IF NOT EXISTS idx_error_record_last ON error_record(last_seen);
CREATE INDEX IF NOT EXISTS idx_error_record_src ON error_record(source, level, status);
```

**指纹归一**（`util/ErrorFingerprint.kt`，纯函数可单测）：去掉数字、十六进制、引号内字面量、空白，
并从堆栈取第一条 `com.example.dq` 栈帧（去掉行号）参与哈希 —— 同一种错误无论参数怎么变都归为一条。

## 四、内核（common）

- `model/ErrorRecord.kt`：`ErrorEvent`（写入入参）、`ErrorRecord`（查询结果）、`ErrorQuery`/`ErrorPage`/`ErrorStats`、
  `ErrorSource`/`ErrorLevel`/`ErrorStatus` 枚举。
- `repository/ErrorRepository.kt`：`upsert`（先 UPDATE 命中则 `occurrences+1`，未命中 INSERT，唯一键冲突回退 UPDATE）、
  `query`（来源/级别/状态/关键词/时间范围 + 分页）、`stats`、`updateStatus`、`delete`、`clear`、
  `purgeBefore`、`trimExcess`（超上限删最旧）。
- `service/ErrorCenterService.kt`：
  - `record(event)` **不阻塞调用线程**：有界队列（2000）+ 单守护写线程批量 upsert；
  - `!ready`（内核迁移未完成）时**同步追加到 `logs/error-spool.jsonl`**，`markReady()` 时回灌入库并删除文件 ——
    保证启动期异常、进程崩溃前的异常不丢；
  - 保留期默认 30 天（`max(1, …)`），单例上限 20000 条，`markReady()` 时执行一次清理；
  - 内部失败用独立 logger `dq.error-center.internal`（被采集器显式跳过，防自噬递归）。
- `env/ServiceEnv.kt`：装配 `ErrorCenterService`，`initDatabase()` 末尾 `markReady()`。

## 五、壳层（server）

- `web/ErrorCaptureAppender.java`：挂到 root logger（与 `LogStreamAppender` 并列，编程式挂载）。
  过滤规则：级别 `ERROR` 全收；`WARN` 仅当带 `IThrowableProxy` 才收；跳过 `dq.error-center.internal`
  与自身 logger。异常链里出现 `SQLException` 记 `DATABASE`，否则 `BACKEND`。
  内核未就绪时自身缓冲（有界 1000），`setSink()` 后回灌。
- `controller/ErrorCenterController.java`：
  - `POST /api/errors/report`（前端上报，批量上限 50 条、体积上限 256KB，超限丢弃并 200 兜底）
  - `GET /api/errors`（分页筛选）、`GET /api/errors/stats`
  - `GET /api/errors/{id}`（详情）
  - `PUT /api/errors/{id}/status`、`POST /api/errors/batch-status`
  - `DELETE /api/errors/{id}`、`POST /api/errors/clear`、`POST /api/errors/purge`
  - `GET /api/errors/export`（Markdown / JSON，便于发给开发）
- `WebServer.java`：`/api/errors` 前缀加入授权放行清单（与 `/api/diagnostics` 同待遇）；
  构造时挂 `ErrorCaptureAppender`；`finishInit` 注入 `ErrorCenterService`（`setSink`）与 `ErrorCenterController`。
- `DqApplication.java`：未捕获线程异常既写 `startup.log`，也 `ErrorCenterService.report(...)`（静态入口）。

## 六、静默 catch 审计

按 `docs/wiki/代码约定与安全.md`：「所有错误都必须落日志，业务 catch 不允许静默吞掉；预期内的降级用 debug/warn 说明后果」。
逐个审查 `common` + `server` 中空 catch / 仅注释的 catch：

- 真正吞掉失败的 → `log.warn("…", e)`（自动进错误中心）；
- 预期内降级（关闭资源、可选探测、能力缺失）→ 补 `log.debug` 说明，不进错误中心。

## 七、前端

- `web/src/utils/errorCapture.js`：
  - `window.addEventListener('error')`（捕获阶段，兼容资源加载失败）
  - `window.addEventListener('unhandledrejection')`
  - Vue `app.config.errorHandler`（组件名 + 生命周期）
  - `console.error` 包装（保留原行为，排除自身与上报失败）
  - 统一 `reportError(payload)`：指纹去重窗口 3s、队列批量 1s / 满 10 条上报、单批上限 50、
    `fetch` + `keepalive`，失败静默（防递归刷屏）。
  - 排除项：`/api/errors/report` 自身失败、401（授权失效属状态、由跳激活页处理）、
    503「服务启动中」（启动就绪前状态）。
- `web/src/main.js`：`installErrorCapture(app, router)` 在 mount 前安装。
- `web/src/api/index.js`：axios 响应错误拦截器里调用 `reportApiError`。
- `web/src/router/index.js`：`/errors` 路由 + 守卫放行（同 `/diagnostics`）+ `MENU_ITEMS` 复用 `diagnostics` key。
- `web/src/App.vue`：侧边栏在「系统诊断」后加「错误中心」入口（`menu: 'diagnostics'`）。
- `web/src/views/Errors.vue`：统计卡片（未处理/今日新增/总计/按来源）、来源+级别+状态+时间+关键词筛选、
  轮询刷新、列表按最近时间倒序、详情抽屉（完整堆栈/上下文/复制）、单条与批量标记已处理/已忽略/删除、
  清空（带确认）、导出 Markdown/JSON。
