# 比对任务批量导入实施计划

> 状态:**已实施**(2026-09-17),方案曾与用户对齐(2026-09-16);实现与本文的少量出入见文末「实施出入记录」。
> 背景:数据比对目前只能走三步向导逐个建任务,现场动辄几十上百张表要比对,人工点选不现实。本功能让填表人用一张 Excel(一 sheet 一任务)批量建任务,大模型只承担字段映射推导这一件重复劳动,人做两道把关:数据源映射确认、字段映射审核。

## 目标

- 上传一张 xlsx,**一个 sheet = 一个比对任务**:首行基准表,其余行对比表;固定 `match_mode=CODE_NAME_LLM`(先编码后名称+大模型归一化)、`compare_mode=COLUMN`(行级+列级)。
- 三步流程:**①数据源确认**(跨 sheet 汇总去重,按 地址+端口+库 匹配已建档数据源,没有的用表格里的用户名/口令新建,两头都没有标异常)→ **②建任务 + 大模型推导字段映射**(身份字段 code/name 优先取表格,缺失才交大模型;任务进「待处理」)→ **③人工审核映射后开始比对**(列表页「字段审核」弹画布确认 / 「编辑」进向导逐步改)。
- 任务状态机扩为:**待处理(PENDING,带原因)** → 运行中 → 完成/失败/取消。待处理是静止状态,不进线程池、不进后台任务中心轮询、服务重启不清理。
- **导入的 Excel 原件留档**:读完不丢弃,按批次落盘保存、**文件名不变**;任务列表能看到该任务来自哪个文件,点击可下载原件。
- **大模型是前置条件**:未配置大模型时导入入口直接拦下(409 提示先完成 AI 配置),不做无大模型降级——没有映射推导,批量建任务就失去了意义。

## 输入 Excel 格式

单文件多 sheet。每个 sheet 表头 12 列(按表头名去空白定位,顺序不限,照 `SampleTableExcelParser` 口径):

**任务名 = 上传文件名(去扩展名) + `-` + sheet 名**(如 `水库台账-表1` 的 sheet「水库信息」→ 任务名 `水库台账-水库信息`);不做大模型命名,不做唯一性约束(现有比对任务名本就允许重复),超长截断 200。sheet 名为空/非法时回退 `<文件名>-<sheet序号>`。

`角色 | 水利对象类型 | 数据源 | 地址 | 端口 | 库名 | 模式 | 表名 | 对象编码字段 | 对象名称字段 | 用户名 | 口令`

| 列 | 口径 |
|---|---|
| 角色 | `基准` / `对比`;首行必须是基准,有且仅有一行基准 |
| 水利对象类型 | **仅基准行填**(任务级信息,对比行留空忽略);必填,取值限内置列表:水库/堤坝/测站/河流/湖泊/水闸/泵站/灌区/取水工程/其他(`WaterObjects.kt` 常量,与导出归档口径一致);缺失或不在列表内 → 落「其他」并在导入报告里提示,不阻塞建任务 |
| 数据源 | 展示/校验辅助列;与按地址匹配到的已建档数据源名不一致时以地址为准,报告里提示 |
| 地址/端口/库名 | **定位数据源的依据**(host 小写 + port + 库名),必填 |
| 模式 | 可空;仅多库方言(SQL Server/Kingbase)需要 |
| 表名 | 必填 |
| 对象编码字段 | 基准行必填(= keyField);对比行**可空**——填了直接锁进映射,没填交大模型推导 |
| 对象名称字段 | 基准行必填(= displayField,match_mode=CODE_NAME_LLM 要求);对比行可空,同上 |
| 用户名/口令 | **可选**;仅当数据源在系统中不存在、需要新建时必填。两头都没有 → 该数据源标异常 |

解析器新增 `service/CompareImportExcelParser.kt`(object 纯函数,照 `SampleTableExcelParser` 写法:XSSFWorkbook + DataFormatter、全空行跳过、非法行进 SkippedRow)。**口令只活在内存**,批次表不落口令列(同抽样导出口径)。

## 流程总览

```
上传 Excel(原件先落盘,文件名不变)
  → 解析全部 sheet,汇总去重数据源(地址+端口+库),逐条匹配已建档数据源
  → 批次置「待确认数据源」,前端弹出映射清单:已匹配 / 待新建(有口令) / 异常(无口令)
  ① 用户确认 → 待新建数据源实测连通后建档(连不上转异常),分组「比对批量导入」
  → 逐 sheet 建任务(状态=PENDING):
      · 身份映射:表格给了 code/name 的直接写死进该目标 mapping,不进推导范围
      · 大模型推导其余字段映射(逐目标串行,场景 COMPARE_MAPPING)
      · 水利对象类型取基准行表格值(不调大模型),任务名 = 文件名-sheet 名(不调大模型)
      · 涉及异常数据源 / 推导失败的目标记原因,任务仍建出
  → 任务列表「待处理」tag + 原因(数据源异常 / 映射待审核),任务名下方显示来源文件名(点击下载原件)
  ②③ 用户逐任务处理:
      · 「字段审核」弹可编辑映射画布 → 确认无误 → 「开始比对」(映射落库,PENDING→RUNNING)
      · 「编辑」进向导预填模式,从第 1 步逐步确认/修改 → 提交(更新任务)后同样可开始比对
```

## 状态机与存储(V59 一个迁移文件)

`compare_job.status` 新增取值 `PENDING`(待处理),现有 RUNNING/DONE/FAILED/CANCELED 不变:

- **PENDING → RUNNING**:仅「字段审核确认」或「向导编辑提交」两个出口;转换时做与 `submit` 相同的校验(目标必须映射到比对主键、目标缺主键列报错等)。
- **PENDING 不进执行器**:`execute` 只接 RUNNING;`recoverUnfinished()` 只处理 RUNNING 残留,不动 PENDING;删除/归档对 PENDING 放行(删除不加 409)。
- 后台任务中心**不轮询** PENDING(它是等用户操作的静止状态),`listActive` 口径不变。

```sql
-- V59__compare_import.sql
ALTER TABLE compare_job ADD COLUMN IF NOT EXISTS pending_reason VARCHAR(32);   -- DS_ERROR / MAPPING_REVIEW / IMPORT_ERROR
ALTER TABLE compare_job ADD COLUMN IF NOT EXISTS object_category VARCHAR(64);  -- 水利对象类型,取自导入表格基准行,可空
ALTER TABLE compare_job ADD COLUMN IF NOT EXISTS import_id BIGINT;             -- 来源批次,向导手工建的为 NULL

CREATE TABLE IF NOT EXISTS compare_import (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  file_name   VARCHAR(512) NOT NULL,          -- 原始文件名(不变)
  file_path   VARCHAR(1024) NOT NULL,         -- 原件落盘路径:数据目录/compare-imports/batch-<id>/<原文件名>
  file_size   BIGINT,
  status      VARCHAR(16)  NOT NULL,          -- DS_REVIEW / BUILDING / DONE / FAILED
  ds_report   CLOB,                           -- 数据源映射报告 JSON:[{key,名称,地址,端口,库名,action,datasourceId,error}]
  task_count  INT NOT NULL DEFAULT 0,         -- sheet 数
  job_ids     VARCHAR(2048),                  -- 建出的任务 id 清单 JSON
  error       VARCHAR(1024),
  created_at  TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  finished_at TIMESTAMP
);
```

`compare_import` 只存到「任务建完」为止,之后生命周期归任务列表管;批次记录**与原件一起长期保留**供溯源(哪个任务从哪张表来的、原表长什么样,随时可下载回查)。

**原件落盘口径**:上传后先把字节流写到 `数据目录/compare-imports/batch-<id>/<原文件名>`(批次 id 先插行占位再写文件,照 `sample-exports/task-<id>/` 的目录惯例;文件名原样保留,仅做路径安全清洗——去掉路径分隔符,防 `../` 注入;同名不冲突,一批次一目录),再解析。解析失败/用户放弃确认,文件也不删——现场排查「当时导的到底是什么」全指望它。

### 1. common(内核)

- **模型** `model/CompareModels.kt`:`CreateCompareJobRequest` 不动;新增 `CompareImportBatch`/`CompareImportView`(批次 + dsReport + jobIds + fileName/fileSize)、`PendingReason` 枚举(DS_ERROR「数据源异常」/MAPPING_REVIEW「映射待审核」/IMPORT_ERROR「导入异常」)。`CompareJobView` 补 `pendingReason`/`objectCategory`/`importId`/`importFileName`(list 查询时按 import_id 左联 compare_import 取 file_name,向导手工建的任务为 null)。
- **解析器** `service/CompareImportExcelParser.kt`:纯函数,上文格式;附 `writeTemplate`(表头 + 基准/对比两行示例)。
- **数据源匹配**:抽样导出的 `keyOfExisting`(按方言从 jdbcUrl 反解 host/port/库名)目前在 `SampleExportService` 内,**抽成共享**(如 `service/DatasourceKeyMatcher.kt`),两处共用;比对导入只按「host+port+库」匹配,不含用户名(表格里用户名是可选项)。
- **服务** `service/CompareImportService.kt`:
  - `submit(file)`:**先把原件落盘**(批次插行拿 id → 写 `compare-imports/batch-<id>/<原文件名>` → 回填 file_path/file_size)→ 解析 → 汇总去重数据源 → 逐条匹配已建档 → 批次落库置 DS_REVIEW,返回批次(含 ds_report)。未配置大模型直接 409(此时文件不落盘,入口即拦)。
  - `downloadFile(id)`:按 file_path 读原件返回(供 controller 流式输出,Content-Disposition 用 file_name 原名)。
  - `confirm(id)`:仅 DS_REVIEW 批次可调用;逐「待新建」数据源实测连通(复用 `testConnectionsConcurrently`,4 线程 + 单条 20s)后建档(分组「比对批量导入」,名称取「数据源」列,重名加后缀),连不上转异常;然后逐 sheet 建任务(见下),批次置 DONE。
  - 建任务:基准行校验(表存在、code/name 字段存在)失败 → 任务建出置 PENDING + IMPORT_ERROR;逐目标组装映射——**表格给了 code/name 的锁定进 mapping、从推导范围剔除**;调 `CompareMappingPrompts` 推导其余字段;目标缺 code/name 的,把身份字段一并纳入推导(提示词动态组装);推导失败/映射不含主键 → 该目标记原因,任务 PENDING + MAPPING_REVIEW;涉及异常数据源 → PENDING + DS_ERROR;全顺 → PENDING + MAPPING_REVIEW(映射一律要人审)。
  - 水利对象类型:取基准行表格值落 `object_category`,缺失/非法落「其他」并在 ds_report 记提示;内置常量列表 `WaterObjects.kt`(水库/堤坝/测站/河流/湖泊/水闸/泵站/灌区/取水工程/其他,V1 内置,后续有需要再做成可配置字典)只做校验与前端下拉选项来源。任务名不走大模型:文件名(去扩展名)+`-`+sheet 名直接拼接。
  - 固定 4 线程池照 `SampleExportService`;**不写暂停/恢复**(建任务是分钟级,不像抽样导出是小时级)。
- **映射 prompt 扩展** `service/CompareMappingPrompts.kt`:`buildPrompt` 增加 `lockedFields: Map<String, String>` 参数(基准字段 → 目标列),组装时从待推导清单剔除并在输出约定里排除;解析侧保持现有容错。**纯函数,改动必须同步单测**。
- **CompareService 扩展**:
  - `createPending(...)`:`CompareImportService` 专用入口,落 job(PENDING)+ targets(含 mapping),不走执行器。
  - `confirmMapping(jobId, mappings: Map<targetId, Map<String,String>>)`:仅 PENDING;校验口径同 `submit`(主键必须被映射、基准字段在 fields 内、目标列存在),全量替换各目标 mapping 后 PENDING→RUNNING 并丢进执行器。
  - `updatePending(jobId, req: CreateCompareJobRequest)`:仅 PENDING;向导编辑模式提交走这里,tx 内替换 job 元数据 + 删旧 targets 重建(照 `rerun` 的清空重建写法,但保留 PENDING,是否立即运行由前端再调 `confirmMapping`/`start`)。
  - `start(jobId)`:仅 PENDING 且 pending_reason != DS_ERROR;PENDING→RUNNING 进执行器(审核弹窗「开始比对」= 先 confirmMapping 再 start,可合并成一个端点 `confirm-and-start`)。
  - `list`/`detail` 返回补 pendingReason/objectCategory;`delete`/`archive` 对 PENDING 放行。
  - **导出文件名改为跟随任务名**:`GET /api/compare-jobs/{id}/export` 的文件名由固定「比对总览-{id}.xlsx」改为 `<任务名>.xlsx`(任务名做 `\/:*?"<>|` → `_` 清洗,空名回退旧格式)——导入任务的任务名本身带文件名+sheet 名,导出件直接可对上来源;此改动对全部比对任务生效(含向导手工建的),导出文件向后兼容铁律只管「导入能读旧文件」,导出改名不违反。
- `env/ServiceEnv.kt`:装配 CompareImportService + DatasourceKeyMatcher。

## 明确不做

- **不做无大模型降级**:未配置大模型 = 导入入口 409。映射推导失败也不退回「按名称自动匹配」,由人工在审核画布上补线(这正是审核存在的意义)。
- **不做暂停/恢复/重新导入**:批次生命周期间短(解析 → 确认 → 建任务),建完即终态;填错了删任务重传(重传产生新批次新文件,旧批次原件仍留档)。
- **不做批次删除与文件清理**:批次记录和原件 xlsx 长期保留(xlsx 体积小,现场溯源价值大于磁盘占用);真要做清理时另起需求,连同 sample-exports 产物一起设计。
- **导入时不表达字段映射列**(基准字段/目标字段两列):身份字段之外的映射全部交大模型,表格保持 12 列。
- **不做大模型命名与分类**:任务名 = 上传文件名 + sheet 名直接拼接;水利对象类型表格里用户自己填(种类就那么多,下拉候选内置,犯不上动用大模型)。大模型在本功能里只剩字段映射推导一件事。
- **水利对象列表 V1 内置常量**(`WaterObjects.kt`,含「其他」兜底),不做字典维护界面;`object_category` 暂只展示,不参与导出归档(后续报告按类别归档时再启用)。
- **待处理任务不进后台任务中心**、不做角标提醒。

## 实施出入记录(2026-09-17 留档)

实施时与上文方案的少量出入,以代码为准:

1. **confirm 是异步的**:`POST /api/compare-imports/{id}/confirm` 不同步返回 `{jobIds}`,而是立即返回 `{ok:true}`
   转后台执行(批次 BUILDING),前端 2s 轮询批次详情到 DONE/FAILED 后从 `jobIds` 字段拿任务清单。
2. **导入 Excel 无「数据库类型」列**:待新建数据源按端口反推类型(`DatasourceKeyMatcher.dbTypeOfPort`:
   3306=MySQL/5432=PostgreSQL/1433=SQLServer/1521=Oracle/5236=DM/54321=Kingbase/2881=OceanBase/5866=HighGo);
   非默认端口推不出 → 不建档,报告记 ERROR「请先在数据源页手工建档后重新导入」,涉及目标的任务记 DS_ERROR
   (基准数据源推不出时整任务不建、报告记 NOTE)。
3. **异常数据源也建档**:实测连不上/缺口令未实测的数据源同样建档(conn_status=ERROR,ds_report 行动作 CREATED
   带 error),便于在数据源页修复后复活任务——`CompareService.confirmMapping` 是 DS_ERROR 任务的复活出口
   (确认时重读两侧字段重验);已建档但 conn_status=ERROR 的数据源不自动复测。
4. **updatePending 后 pending_reason 归一为 MAPPING_REVIEW**(`CompareRepository.replacePendingJob`:
   编辑后映射仍需人工审核),进度/错误清零,保持 PENDING 与 import 溯源列不动。
5. **ds_report 的 sheet/行级提示以 action="NOTE" 行承载**(跳过的 sheet/行、水利对象类型落「其他」、
   基准数据源无法建档未建任务、目标数据源无法建档未加入任务等),不占数据源条目。
6. **字段映射推导改异步、连接实测挪后台**(2026-09-16):confirm 不再阻塞等实测与大模型——批次只做
   「数据源同步插行 + 逐 sheet 建任务」秒级动作即置 DONE(待新建有口令的先插行 conn_status 空=未实测,
   无口令的照旧直接标 ERROR);任务落 PENDING + 新原因 `MAPPING_RUNNING`(映射推导中,审核/编辑/直启
   一律拒绝),涉及异常数据源的直接 DS_ERROR 不进推导队列。映射线程池(固定 4 线程,与建任务池分离)
   逐任务推进:先实测待新建数据源(**批次内同 dsId 去重只测一次**,单条 20s 仍走 ConnectionTester),
   失败 → 数据源转 ERROR、任务转 DS_ERROR;连通后做基准表校验(失败整任务转 IMPORT_ERROR,身份字段
   按表格原值兜底)并归一实际列名,再逐目标串行调大模型推导,完成转 MAPPING_REVIEW。基准表校验随之从
   confirm 阶段挪到后台(phase 1 不连业务库,待新建数据源可能连不上,避免拖住批次)。重启残留
   MAPPING_RUNNING 由 `CompareService.recoverUnfinished` 转 MAPPING_REVIEW 记「应用重启,映射推导中断,
   请人工审核补线」(审核画布补线即复活)。前端:MAPPING_RUNNING 显示蓝色「映射推导中」加载 tag 并
   保持列表 1s 轮询,推导期间不显示「字段审核」「编辑」。实现曾短暂试过一个独立的
   `compare_job.mapping_status` 列方案(未发布,已随本改动收回),最终仍以 pending_reason 单字段承载。
7. **模板换为客户提供的 15 列格式**(2026-09-17,功能未发布故旧 12 列模板直接废弃、不做双格式兼容):

   表中文名称 | 表英文名称 | 是否基准表 | 对象编码字段 | 对象名称字段 | 是否纳入采集范围`。配套口径变化:
   「是否基准表」(是/否)取代「角色」列,基准行按该列定位、**不再要求首行**,零行/多行仍整 sheet 跳过记 NOTE;
   「数据库类型」显式必填(取值口径照抽样导入),**删除端口反推类型兜底**(`DatasourceKeyMatcher.dbTypeOfPort` 删除),
   数据源匹配 key 加入类型(类型+host小写+port+库名,`DatasourceKeyMatcher.locationKey` 改带类型;
   抽样导出侧 fullKey 口径不变);「所属水利对象类别名称」改自由文本原样落 `object_category`、空则留空,
