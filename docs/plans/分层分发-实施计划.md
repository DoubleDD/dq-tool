# 分层分发改造:业务层(jar+前端)独立动态分发实施计划

> **已实施**(2026-09-19,feature/biz-layer-distribution 合并回 main)。
> 实施与本文的出入以代码注释与 [tauri/AGENTS.md](../../tauri/AGENTS.md) 为准,主要有三处:
> ① zip crate 复用 Cargo.lock 已锁的 4.x(不再引入 2.x);② 壳版本取 `app.package_info().version`
> (tauri.conf.json),不是 `CARGO_PKG_VERSION`(后者恒为 0.1.0);③ static 根在重启/回滚**就绪成功后**
> 才切换(而非每请求重读 current 指针),避免切换窗口期旧页面懒加载 chunk 拿到新版文件造成混版。

## 目标与分层

把 dq-tool 的 Tauri 交付物按变化频率分三层,更新时只分发业务层:

- **系统层**:Tauri Rust 壳(托盘/侧车/IPC/更新器),极少变
- **runtime 层**:完整 JRE(`resources/jre/`),极少变
- **业务层**:server fat jar + 前端 `web/dist`,一天几个版本,更新只发这一层

已确认的决策:
- 版本化目录 `versions/x.x.x/`,**只留最近 2 个版本**(当前 + 上一个),一个版本的全部业务文件放进同一目录
- **绿色免安装版也启用业务层自动更新**(原地换文件,不再有 NSIS 破坏绿色形态的问题)
- **保留 tauri-plugin-updater 全量通道做兜底**:业务包声明 `minShell`,壳太旧时回退全量安装包更新
- macOS 不在本期范围(macos-tauri CI 本就停用);jpackage 浏览器形态维持整包分发,不改

## 目标目录布局(安装版 Windows,绿色版同理锚定 exe 旁)

```
<安装目录>/resources/
  jre/                          # runtime 层,不动
  versions/
    current                     # 文本文件,内容 = 当前版本号(如 2.0.15),原子写(临时文件+rename)
    2.0.15/
      dq-tool.jar
      static/                   # web/dist 全量(index.html + assets/...)
      manifest.json             # 业务包元信息(version 一致性校验用)
    2.0.14/                     # 上一版本,回滚兜底
```

- `current` 指针文件是「哪个版本生效」的唯一来源(不靠最大 semver 猜,回滚后旧版本即为 current)
- 安装包(全量)只内嵌一个 baseline 版本目录;业务更新新增版本目录
- GC:启动时(后端拉起前)保留 current + 其余中 semver 最高者,删除更老目录;current 缺失/损坏时取最高 semver 兜底
- 开发模式(debug_assertions)完全不走 versions:沿用 `server/build/libs` 最新 jar + 仓库 `web/dist`,行为不变

## 改造步骤(实际落地)

### 1. 壳层:webview 从磁盘加载前端(替代 frontendDist 内嵌)

- `tauri.conf.json` 删除 `build` 段(只含 frontendDist),exe 不再内嵌前端
- `protocol.rs`:`register_uri_scheme_protocol("dq", ...)` 按请求路径从当前 static 根读文件;
  `/` 与无扩展名路径回退 index.html(createWebHistory),有扩展名缺失 404;拒绝 `..`/`%`/`\` 穿越;
  mime_guess 给 Content-Type
- 窗口 URL `WebviewUrl::External("dq://localhost/index.html")`;Tauri 2.11.5 对用户注册的自定义协议
  按 local 来源处理(`is_local_url` 第三分支,Windows `http://dq.localhost` 映射已覆盖),
  capabilities 无需 remote.urls;wry 0.55.1 在 Windows 导航时自动做 workaround 映射
- 冒烟实测(2026-09-19 macOS dev):后端日志 `Origin=dq://localhost`,页面加载、IPC、token 全通

### 2. 壳层:后端拉起重构为「版本目录 + 失败回滚」(backend.rs / versions.rs)

- `resolve_current`:读 current → 校验完整性 → 失败回落最高版本号目录 → 都没有 fatal
- `BackendManager`:spawn/restart/wait_ready/kill,命令行组装(数据目录/G1GC/Xmx/AOT/token/端口避让/
  CREATE_NO_WINDOW)行为不变;启动监督 `supervise_startup`:就绪失败回滚次新版一次(`rollback_once`),
  再失败 fatal;业务更新复用同一原语(更新路径回滚失败不 fatal,重启即恢复)
- `bundled_resources_dir()` 判据从 `backend/dq-tool.jar` 改为 `versions/` 目录存在

### 3. 壳层:业务层自动更新通道(bizupdate.rs)

- 清单 `https://github.com/DoubleDD/dq-tool/releases/latest/download/business-latest.json`
  (`DQ_BUSINESS_MANIFEST` 可覆盖),字段:version/url/signature/minShell/notes
- 与全量 updater 同线程串联(30 分钟轮询,先业务后全量);`update-skipped.txt` 两通道共用
- 预下载 zip → minisign 验签(与全量同一把密钥对)→ 解压校验(dq-tool.jar + static/index.html +
  manifest.json 版本一致)→ 询问 → 切 current → GC 留新旧两版 → 重启 → 就绪后 location.reload()
- 启用:安装版 + 绿色版;macOS 与开发模式禁用;minShell 超壳版本交回全量通道

### 4. 打包脚本(scripts\package-tauri-win.bat / package-tauri-win-portable.bat / start-browser.bat)

- 资源组装改为 `resources\versions\<v>\` 布局 + `current` 指针;版本号从 VERSION 文件读取去 `0.` 前缀
- 绿色版不再重复落 `resources\static`;`start-browser.bat` 探测 versions 布局(jpackage 分支不变)
- `scripts/package-tauri-mac.sh` 本期未动(mac 业务更新不启用;恢复 mac 构建时需同步 versions 布局)

### 5. CI(release.yml)

- `windows-tauri` 任务新增「Build business package」:`resources\versions\<v>\` 打成
  `dq-tool-<v>-business.zip`(跨平台通用)传 artifact
- 新增 `business-manifest` 收尾任务(tag 触发):ubuntu 上 minisign 签名(私钥集中一处,
  `.sig` 为 base64 单行约定)并生成 `business-latest.json` 挂 Release;`BIZ_MIN_SHELL=2.0.15`
  常量(首个支持业务更新的壳版本,壳层出现业务层依赖的变更时才上调)
