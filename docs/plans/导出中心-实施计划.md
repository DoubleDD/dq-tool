# 导出中心实施计划

> 状态:**已实施**(2026-09-18, wiki 见 [导出中心](../wiki/导出中心.md))。
> 实施时对原稿的修正:① 迁移号 V66(原稿 V51 被占用);② **V67 起按用户决策改为 push 模型**(导出一个文件出一条记录,记录相对数据目录路径/大小/描述/时间;落盘类由写入方直推,V66 的 UNION 归一与「仅同步类可删」随之废弃);③ 原稿「不存在 id 404」按全应用约定落地 400;另原稿提到的 CompareDiff 裸下载修复与 `save_download_as` 均已随直存改造完成(`downloadFile` 统一封装)。
> 背景:系统现有 15 处文件导出,散落各模块;其中 12 处是「请求即生成、响应完即消失」的同步流式导出,无任何留痕,用户导出后想找回「导的是什么、从哪导的」都无据可查。已有任务表落盘的只有报告导出与抽样导出两处。

## 目标

- 新增「导出中心」一级页面,**所有**导出文件统一可查到:类型、描述、文件名、大小、状态、时间。
- 支持筛选(类型/关键字/时间范围)、下载/重新导出、删除记录。
- 纯增量:不改任何现有导出的行为与文件格式,不影响导出文件向后兼容铁律(本功能只记元数据,不碰导出文件本身)。

## 方案总览:登记制(hybrid)

- 新增 `export_record` 表,只记**元数据**,不强制落盘。
- **同步类导出**(扫描 Excel/Word、整库结构 Word、预览 xlsx、比对 xlsx、列表导出、4 种 JSON 传输):各 controller 埋点写记录;「重新导出」= 按记录参数重调原端点(注意:是重新生成,结果可能不同,UI 文案用「重新导出」不用「下载」)。
- **异步落盘类**(报告 Word `report_export`、抽样 zip `sample_export`):已有任务表 + 磁盘产物,**不双写** `export_record`;查询层(repository)把三表 UNION 成统一模型,列表/详情零侵入;操作复用各自原有端点(下载/打开目录)。
- 诊断报告 .md 为纯前端生成、不经后端,V1 不纳入。
- 局域网 share 出口(`LanController`)是实例间通道、无浏览器下载入口,不记。
- `list-exports` 一次性 token 取走即删、不可重放:记一条纯历史(操作列无「重新导出」)。

## 改动清单

### 1. common(内核)

- 新增 `common/src/main/resources/db/migration/V51__export_record.sql`
  ```sql
  CREATE TABLE IF NOT EXISTS export_record (
    id           BIGINT AUTO_INCREMENT PRIMARY KEY,
    kind         VARCHAR(32)  NOT NULL,  -- 导出类别,见 ExportKind 枚举
    title        VARCHAR(512) NOT NULL,  -- 语义化描述(数据源/表/任务),前端展示
    file_name    VARCHAR(512) NOT NULL,  -- Content-Disposition 文件名
    file_size    BIGINT,                -- 同步流式导出未知大小为 NULL;list-exports 内存数组有大小
    params_json  VARCHAR(2048),         -- 重新导出所需 API 路径等,{"path":"/api/scans/12/export"}
    status       VARCHAR(16)  NOT NULL DEFAULT 'SUCCESS',
    error        VARCHAR(1024),
    created_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP
  );
  CREATE INDEX IF NOT EXISTS idx_export_record_created ON export_record(created_at DESC, id DESC);
  ```
- 新增 `model/ExportRecord.kt`:`ExportKind` 枚举(SCAN_EXCEL/SCAN_WORD/DBSTRUCT_WORD/PREVIEW_XLSX/COMPARE_XLSX/LIST_XLSX/TRANSFER_DATASOURCE/TRANSFER_METADATA/TRANSFER_SCAN/TRANSFER_ANNOTATION/TEMPLATE)+ `ExportRecord` data class + 查询用 `ExportCenterItem`(统一模型:id 复合字符串 `kind:源表id`、kind、title、fileName、fileSize、storage(NONE/DISK)、status、downloadPath(可空)、openDir 布尔、createdAt、finishedAt、error)。
- 新增 `repository/ExportRecordRepository.kt`:insert、分页列表(与 report_export/sample_export UNION ALL,统一按 created_at DESC 排序,LIMIT/OFFSET;总数用 COUNT 包裹 UNION 子查询)、按 id 删除、按 kind+源 id 解析删除。H2 方言,无库差异。
  - UNION 映射口径:report_export → kind=REPORT_DOCX、storage=DISK、downloadPath=`/api/report-exports/{id}/download`、openDir=true、status 直接映射(PENDING/RUNNING/DONE/FAILED→统一状态);sample_export → kind=SAMPLE_ZIP、storage=DISK、downloadPath=`/api/sample-exports/{id}/download`、openDir=true。
  - 筛选参数:kind 等值、keyword 对 title/file_name LIKE、created_at 起止;status 仅对任务表侧有意义,同步类恒 SUCCESS,SQL 里统一过滤即可。
- 新增 `service/ExportCenterService.kt`:列表/删除编排 + `record()` 供各导出埋点调用(kind/title/fileName/fileSize/params,组装 ExportRecord 落库;内部 JSON 用 Jackson 2,遵守内核约定)。**只做记录,不感知 Web 层**。
- `env/ServiceEnv.kt`:装配 ExportRecordRepository + ExportCenterService。

### 2. server(Javalin 壳层)

- 各 controller 埋点(统一在写完响应流后调 `exportCenterService.record(...)`,失败不记,V1 只记成功):
  - `ScanController.java:72/84/97` —— title 形如「扫描任务 #12 结果」「数据源 xxx·schema 最新扫描结果」「扫描任务 #12 表结构文档」,params.path 记本端点路径(含实际 id)。
  - `MetadataController.java:146` ——「数据源 xxx 整库表结构」。
  - `PreviewController.java:32` ——「数据源 xxx·schema·table 数据预览」,params 记含 where/orderBy 的完整 query(重新导出口径与首次一致)。
  - `CompareController.java:81` ——「比对任务 #id 差异报告」。
  - `ListExportController.java:28` —— stage 成功时记,params_json 置空(不可重放)。
  - `DataSourceController.java:153/177`、`ScanTransferController.java:29`、`AnnotationController.java:27` —— params 记含 ids 的完整 query。
  - `SampleExportController.java:63`(模版,可选)。
- 新增 `controller/ExportCenterController.java`
  - `GET /api/export-center?kind=&keyword=&start=&end=&page=&size=` → 分页列表 `{total, items}`。
  - `DELETE /api/export-center/{kind}/{id}` → 仅同步类(kind ∈ ExportKind)允许,删 export_record 行;REPORT_DOCX/SAMPLE_ZIP 返回 409(产物管理仍归原页面;报告任务当前无删除端点,V1 不动)。
- `web/WebServer.java`:注册上述路由(照现有 controller 注册方式)。

### 3. web(前端)

- 新增 `views/ExportCenter.vue`:照抄 `ReportExports.vue` 范式(`.page-card` + `.toolbar` + `.toolbar-actions` + 状态 tag 映射 + keep-alive 生命周期)。
  - 列:类型(tag)/描述(title)/文件名/大小(NONE 显示「—」)/状态/时间/操作。
  - 操作列按 storage 区分:全部支持「删除」(同步类);NONE 类有「重新导出」(downloadFile(downloadPath));DISK 类有「下载」(原 download 端点)+「打开目录」(report/sample 复用原 open/open-dir 端点)。
  - 筛选:类型下拉、关键字输入、时间范围(el-date-picker)、刷新按钮。
  - 轮询:存在 PENDING/RUNNING 项时 2s 轮询(照 ReportExports.vue `hasActive/startPolling` 写法),全终态停止。
- `router/index.js`:加 `{ path: '/export-center', ... }`;`App.vue` navs 加一项(图标 `Download`);`stores/tabs.js` PAGE_TABS 加 `'/export-center': '导出中心'`。授权:普通功能恒显示,不加 feature 门。
- `api/index.js`:加 `listExportCenter(params)` / `deleteExportCenter(kind, id)`。
- 顺带修复:`views/CompareDiff.vue:499` 裸 `a.click()` 未走 `downloadFile` 公共封装(Tauri 下相对 URL 可能失效),改为 `downloadFile('/api/compare-jobs/' + jobId + '/export')`。
- Tauri:无需改 Rust;「下载/重新导出」都经 `downloadFile` → Rust `save_download_as`,「打开目录」复用现有端点。

## 明确不做

- 同步导出**不落盘集中管理**(变「文件仓库」需改写全部同步导出生成方式 + 磁盘清理策略 + Tauri 另存为联动,是另一个量级的活,本期不做)。
- 不双写 report_export/sample_export 到 export_record,不改两张任务表结构。
- 不记导出失败(同步导出异常时响应已中断,V1 只记成功;任务表侧 FAIL 已可见)。
- 不纳入诊断报告 .md(纯前端生成)与局域网 share 出口(实例间通道)。
- 不做导出统计页/角标提醒。
