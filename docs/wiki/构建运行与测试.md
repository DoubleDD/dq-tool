# 构建运行与测试

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。

## 构建与运行

要求:JDK 25+、Node 24+(仅开发模式)。构建用仓库自带 Gradle wrapper,无需安装 Maven/Gradle。

```bash
# 开发模式:后端 10000 + 前端 5173(代理 /api 到 10000)
./gradlew :server:run
cd web && pnpm install && npm run dev

# 交付:单 jar 内嵌前端 —— shadowJar 自动构建前端(无需手动先 build)
./gradlew :server:shadowJar        # buildWeb 任务先跑 npm run build,processResources 再把 web/dist 拷进 jar 的 static/
java -jar server/build/libs/dq-tool-0.1.6.jar   # 访问 http://localhost:10000
```

前端构建由 `server/build.gradle.kts` 的 `buildWeb` 任务(Exec 执行 `npm run build`)作为 `processResources` 的强前置依赖自动完成:
- **增量**:仅 `web/src`、`web/index.html`、`web/vite.config.ts`、`web/package.json` 变化时才真正执行 npm build,未变化时跳过(秒级);
- `web/dist` 缺失时自动重建,**不再产出"旧版/缺失"的静默坏包**(修复过 jar 内 index.html 引用的 JS 与 assets 不一致导致的 MIME 报错);
- `web/node_modules` 缺失时直接报错并提示 `cd web && pnpm install`,不会静默跳过。
- **前端依赖统一由 pnpm 管理**(2026-08):本地开发与 CI 都只认 `web/pnpm-lock.yaml`(lockfileVersion 9),CI 用 `pnpm install --frozen-lockfile`(等价 npm ci,与 lock 失同步即报错),`web/package.json` 的 `packageManager` 字段固定 `pnpm@11.7.0`;历史遗留的 `web/package-lock.json` 已删除——此前依赖变更只同步了 pnpm lock、漏更新 npm lock,导致 CI 的 `npm ci` 报 EUSAGE 缺失 codemirror 等包。**tauri/ 目录同批迁移**:lock 唯一来源 `tauri/pnpm-lock.yaml`,npm 的 `tauri/package-lock.json` 已删除;脚本执行(`npm run build`/`npm run dev`/`npm run tauri`)不变,只对 pnpm 装的 node_modules 跑脚本。
- **Element Plus 按需引入**(2026-08 启动优化):`web/vite.config.ts` 挂 `unplugin-vue-components` + `ElementPlusResolver`,模板里的 `el-*` 组件与样式自动注入;`main.js` 只补 `base.css`/暗色 css-vars/`notification`/`message-box`/`loading` 样式并手动注册 `v-loading` 指令(`ElLoading.directive`);函数式组件保持显式 import(提示统一用 `utils/notify.js` 的 ElMessage 兼容层,底层为 ElNotification),locale 由 `App.vue` 的 `el-config-provider` 提供。入口 chunk 从全量 ~1MB 降到 ~400KB(gzip ~150KB)。
- **dev 依赖预打包**(2026-08 修复菜单点击闪启动页):按需引入生成的 `element-plus/es/components/<组件>/style/css` 样式导入对 vite 启动依赖扫描不可见——首次进入用到新组件的页面时才会被运行时发现,触发 vite 重新预打包并**整页刷新**(页面闪 index.html 启动占位)。`vite.config.ts` 在 `optimizeDeps.include` 里启动时全量预打包应用直接依赖 + 全部 element-plus 组件样式子模块(`elementPlusComponentStyleCss()` 用 `node:fs` 枚举 `node_modules/element-plus/es/components/*`,枚举失败静默降级为空清单),运行期不再有新依赖发现,菜单/页签/面包屑切换全程零整页刷新。仅影响 dev 服务器启动耗时(预打包多花数秒),生产构建不受影响。

静态资源缓存策略(2026-09 起为**内存缓存自实现**,不再用 Javalin CLASSPATH 静态条目):WebServer 构造时把 `static/` 全量(web/dist 仅约 3.4MB)一次性预读进 `staticCache`(`/`、`/assets/{name}` 显式路由 + SPA 回退共用),请求期零 jar I/O——Javalin 7 的 `ClasspathResource` 每个请求都 `openConnection` 且 `setUseCaches(false)`,浏览器每请求一个 js/css 都要重开 75MB fat jar 重析中央目录,异常被静默吞掉按 404;Windows 杀软对新装未签名 jar 的每次打开都实时扫描,首次安装/重启后并发资产请求易被卡住或拒绝,表现为「入口 200(SPA 回退走的是共享 JarFile)、assets 404」(反编译字节码证实)。响应头口径不变:`/assets/**` 指纹资源(文件名带内容 hash)发 `Cache-Control: public, max-age=31536000, immutable`;`index.html` 与 SPA 回退响应发 `no-store` 禁止任何缓存复用(`no-cache` 在浏览器会话恢复/重校验失败等场景仍可能给出旧副本,升级换包后旧入口引用新包已删除的旧 hash 资源,入口 js/css 404 卡死启动页)。SPA 回退只对路径末段无扩展名的 GET 生效;带扩展名的静态文件缺失一律真实 404,不回退 HTML(2026-08 修复免安装版升级后白屏)。另设 `/api/assets-manifest`(与 /api/health 同批放行闸门),启动页复核失败资源时与之比对裁决「版本错配 vs 本机拦截」。预读失败的资源最多再重试 2 轮(间隔 300ms,防杀软连启动期那趟读取也拦截),启动日志固定输出「静态资源 N/M 加载」汇总,最终仍缺失的逐个列出(会话期将 404,现场对照 assets-manifest 排查)。

所有 JVM 启动入口(gradle run、Makefile、jpackage/tauri 安装包)统一使用 G1 + 384MB 堆上限(`-XX:+UseG1GC -Xmx384m -XX:MaxRAMPercentage=50`);桌面单机小堆场景下 ZGC 的内部结构开销大于收益,G1 空闲时还会把堆归还给操作系统。

启动时序与就绪探针(2026-08 启动优化):WebServer 构造只做轻量外壳(静态资源 + 就绪探针 + **路由引用骨架**,控制器由 `finishInit` 注入 AtomicReference),共享内核重活(H2 池 + 业务对象图 + 建表/迁移 + 中断/报告任务恢复)由 `kernel-init` 后台线程与 Web 装配/端口绑定/开窗**完全并行**(DqApplication 提前启动,`finishInit(kernelFuture)` 只 join 结果,内核异常原样抛回 main 走统一失败路径),`start` 绑定端口后即开窗、静态页面秒出。期间业务接口由就绪闸门统一返回 503 + Retry-After,`/api/health` 返回 503 starting + `stage`(StartupStage:1 加载配置/2 启动服务/3 初始化数据);前端 `main.js` 挂载应用前轮询 `/api/health`(200ms 间隔,60s 超时兜底),轮询到 200 才 mount 并加载数据,占位页按 stage 点亮"加载配置/启动服务/初始化数据"步骤,避免白屏与接口报错刷屏。

日常操作也可以用根目录的 `Makefile`(`make` 查看全部):`make dev` / `make dev-headless` / `make dev-web`(开发;`dev`/`dev-headless` 只启动后端 `:server:run`、**不构建前端**,纯前端调试热更新用 `dev-web`(5173,代理 /api 到 10000),后端要服务前端时用磁盘上已有的 `web/dist`)、`make dev2`(起第二个实例,带窗口/托盘,多实例/局域网共享调试;`PORT=10001` 可改,数据目录 `.dev2/data-端口`、日志 `.dev2/logs`,与主实例的 `./data` 隔离故不触发单实例锁)、`make build` / `make run`(jar)、`make test`、`make package`(mac dmg)/ `make package-linux`(deb)/ `make package-win`(Windows 免安装 zip,仅 Windows 可用)、`make tauri` / `make package-tauri`(Tauri 2 套壳版开发运行 / Tauri 套壳 mac dmg,Windows 对应 `make package-tauri-win`,均带 `-skip` 跳过构建变体)、`make clean`;macOS 上会自动探测 JDK 25 覆盖 JAVA_HOME,`dev`/`run` 显式带 `-Djava.awt.headless=false`(否则应用默认 headless,窗口和托盘都不会启动),服务器方式调试用 `make dev-headless` / `make run-headless`。

前端构建与后端运行解耦(2026-08 拆分):`buildWeb`(增量 `npm run build`)不再挂在 `processResources` 上,`:server:run`(dev 模式)与 `:server:test` 之外的日常运行都不触发前端构建;release 打包正确性由新增的 `buildWebForRelease` 保障——它依赖 `buildWeb` 并校验 `web/dist/index.html` 存在,是 `:server:shadowJar` 的显式前置(`make build` / 打包脚本 / CI 均经此路径);`processResources` 无条件 `from(web/dist)` 拷入 classpath `static/` 并把 dist 声明为可选输入(缺失时 from 空目录静默跳过,配合 dev-web 做 API-only 调试;不能配置期 `if` 判断——否则 buildWeb 同轮新建的 dist 会赶上 processResources 已被 up-to-date 跳过,static 拷不进去),并用 `mustRunAfter(buildWeb)` 保证 release/test 场景先构建后拷贝;`:server:test` 显式依赖 `buildWeb` 以保持 WebServerSmokeTest 的静态资源断言完整。运行侧配套:`WebServer` 对 `/static` 静态资源按 classpath 存在与否条件注册(Javalin 对缺失目录直接抛异常),dev 模式无 `web/dist` 时跳过注册、仅日志提示,API-only 调试不受影响;SPA 404 回退在 `index.html` 缺失时返回 JSON 404。

## 测试

```bash
./gradlew :common:test :server:test
```

- common 模块(业务测试主战场):方言 SQL 生成、规则谓词转义、分段键选择、分段累加 == 全表单条 SQL、任务删除级联清理(ScanJobDeleteTest)、授权码编解码(LicenseCodecTest)、表标记(TagServiceTest/TagRepositoryTest:重名冲突、空表标记保护与联动、级联解除、统计口径)、Flyway 迁移新库/老库/已最新跳过三条路径(FlywayMigrationTest)、扫描后生成表描述开关/跳过/熔断(ScanDocServiceTest)、标记与描述数据导入导出合并规则(AnnotationTransferServiceTest)、Jackson 3 消费 Kotlin 模型的 spike(Jackson3KotlinSpikeTest)
- server 模块:WebServer 起停 + 关键端点冒烟(WebServerSmokeTest,临时数据目录)
- Testcontainers 集成测试(需要 Docker):MySQL 8 / PG 15 / SQL Server 2019 真实容器上的并发分段全链路、空值规则、注释、导出
  - OrbStack 用户若报 "Could not find a valid Docker environment":
    `DOCKER_HOST=unix://$HOME/.orbstack/run/docker.sock ./gradlew :common:test`
  - Testcontainers 版本固定 1.21.4(gradle/libs.versions.toml 有注释:旧版默认 API 1.32 被 Docker 29+ 拒绝;不用 2.x,模块坐标有变化)
- **达梦 / 人大金仓 / OceanBase / Oracle / 瀚高 无自动化覆盖**,相关方言改动只能接真实环境手动验证(`docker-test-env/` 有 SQL Server、Oracle 23c 和 Oracle 11g XE 的 compose;11g XE 走 `wnameless/oracle-xe-11g-r2`,amd64 镜像在 Apple Silicon 上需 Rosetta,仅首次建库时执行 `oracle/initdb-11g/` 初始化脚本)
- **LLM 实际调用无自动化覆盖**(prompt 组装有单测),AI 表说明功能需配置真实接口后手动验证
