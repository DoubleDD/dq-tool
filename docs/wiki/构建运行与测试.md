# 构建运行与测试

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。

## 构建与运行

要求:JDK 25+、Node 24+(仅开发模式)。构建用仓库自带 Gradle wrapper,无需安装 Maven/Gradle。

```bash
# 开发模式:后端 10000 + 前端 5173(代理 /api 到 10000)
./gradlew :server:run
cd web && npm install && npm run dev

# 交付:单 jar 内嵌前端 —— shadowJar 自动构建前端(无需手动先 build)
./gradlew :server:shadowJar        # buildWeb 任务先跑 npm run build,processResources 再把 web/dist 拷进 jar 的 static/
java -jar server/build/libs/dq-tool-0.1.6.jar   # 访问 http://localhost:10000
```

前端构建由 `server/build.gradle.kts` 的 `buildWeb` 任务(Exec 执行 `npm run build`)作为 `processResources` 的强前置依赖自动完成:
- **增量**:仅 `web/src`、`web/index.html`、`web/vite.config.ts`、`web/package.json` 变化时才真正执行 npm build,未变化时跳过(秒级);
- `web/dist` 缺失时自动重建,**不再产出"旧版/缺失"的静默坏包**(修复过 jar 内 index.html 引用的 JS 与 assets 不一致导致的 MIME 报错);
- `web/node_modules` 缺失时直接报错并提示 `cd web && npm install(或 npm ci)`,不会静默跳过。
- **Element Plus 按需引入**(2026-08 启动优化):`web/vite.config.ts` 挂 `unplugin-vue-components` + `ElementPlusResolver`,模板里的 `el-*` 组件与样式自动注入;`main.js` 只补 `base.css`/暗色 css-vars/`message`/`message-box`/`loading` 样式并手动注册 `v-loading` 指令(`ElLoading.directive`);函数式组件(`ElMessage` 等)保持显式 import,locale 由 `App.vue` 的 `el-config-provider` 提供。入口 chunk 从全量 ~1MB 降到 ~400KB(gzip ~150KB)。

静态资源缓存策略(WebServer 静态条目 + SPA 回退):`/assets/**` 指纹资源(文件名带内容 hash)发 `Cache-Control: public, max-age=31536000, immutable`;`index.html` 与 SPA 回退响应发 `no-cache` 每次重校验——否则升级后浏览器仍用旧 `index.html` 引用已不存在的旧 hash 资源,模块脚本拿到回退的 `text/html` 报 MIME 错误白屏。SPA 回退只对路径末段无扩展名的 GET 生效;带扩展名的静态文件缺失一律真实 404,不回退 HTML(2026-08 修复免安装版升级后白屏)。

所有 JVM 启动入口(gradle run、Makefile、jpackage 安装包)已统一使用 ZGC(`-XX:+UseZGC`,JDK 25 默认即为分代模式,无需其他参数)。

启动时序与就绪探针(2026-08 启动优化):WebServer 构造只做轻量外壳(静态资源 + 就绪探针 + **路由引用骨架**,控制器由 `finishInit` 注入 AtomicReference),共享内核重活(H2 池 + 业务对象图 + 建表/迁移 + 中断/报告任务恢复)由 `kernel-init` 后台线程与 Web 装配/端口绑定/开窗**完全并行**(DqApplication 提前启动,`finishInit(kernelFuture)` 只 join 结果,内核异常原样抛回 main 走统一失败路径),`start` 绑定端口后即开窗、静态页面秒出。期间业务接口由就绪闸门统一返回 503 + Retry-After,`/api/health` 返回 503 starting + `stage`(StartupStage:1 加载配置/2 启动服务/3 初始化数据);前端 `main.js` 挂载应用前轮询 `/api/health`(200ms 间隔,60s 超时兜底),轮询到 200 才 mount 并加载数据,占位页按 stage 点亮"加载配置/启动服务/初始化数据"步骤,避免白屏与接口报错刷屏。

日常操作也可以用根目录的 `Makefile`(`make` 查看全部):`make dev` / `make dev-web`(开发;`dev`/`dev-headless` 会在 `web/src` 有改动时先自动重建 `web/dist`,纯前端调试热更新用 `dev-web`)、`make build` / `make run`(jar)、`make test`、`make package`(mac dmg)/ `make package-linux`(deb)/ `make package-win`(Windows 免安装 zip,仅 Windows 可用)、`make tauri` / `make package-tauri`(Tauri 2 套壳版开发运行 / Tauri 套壳 mac dmg,Windows 对应 `make package-tauri-win`,均带 `-skip` 跳过构建变体)、`make clean`;macOS 上会自动探测 JDK 25 覆盖 JAVA_HOME,`dev`/`run` 显式带 `-Djava.awt.headless=false`(否则应用默认 headless,窗口和托盘都不会启动),服务器方式调试用 `make dev-headless` / `make run-headless`。

## 测试

```bash
./gradlew :common:test :server:test
```

- common 模块(业务测试主战场):方言 SQL 生成、规则谓词转义、分段键选择、分段累加 == 全表单条 SQL、任务删除级联清理(ScanJobDeleteTest)、授权码编解码(LicenseCodecTest)、表标记(TagServiceTest/TagRepositoryTest:重名冲突、空表标记保护与联动、级联解除、统计口径)、Flyway 迁移新库/老库/已最新跳过三条路径(FlywayMigrationTest)、Jackson 3 消费 Kotlin 模型的 spike(Jackson3KotlinSpikeTest)
- server 模块:WebServer 起停 + 关键端点冒烟(WebServerSmokeTest,临时数据目录)
- Testcontainers 集成测试(需要 Docker):MySQL 8 / PG 15 / SQL Server 2019 真实容器上的并发分段全链路、空值规则、注释、导出
  - OrbStack 用户若报 "Could not find a valid Docker environment":
    `DOCKER_HOST=unix://$HOME/.orbstack/run/docker.sock ./gradlew :common:test`
  - Testcontainers 版本固定 1.21.4(gradle/libs.versions.toml 有注释:旧版默认 API 1.32 被 Docker 29+ 拒绝;不用 2.x,模块坐标有变化)
- **达梦 / 人大金仓 / OceanBase / Oracle 无自动化覆盖**,相关方言改动只能接真实环境手动验证(`docker-test-env/` 有 SQL Server 和 Oracle 的 compose)
- **LLM 实际调用无自动化覆盖**(prompt 组装有单测),AI 表说明功能需配置真实接口后手动验证
