# 前端页面与按钮逻辑

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。本文覆盖前端(web/)页面结构、页面间导航与各页面按钮/交互控件的触发逻辑,是改前端代码前先读的导航手册。

## 总体框架

- 技术栈:Vue 3 + Element Plus + vue-router + axios(基址与令牌由 `web/src/api/base.js` 注入:浏览器/jpackage 同源 `/api`,Tauri 经 IPC `api_base()` 取动态端口与 token,请求带 `X-Dq-Token` 头)。API 层统一走 `web/src/api/index.js` 的 axios 实例:401(非 license 接口)整页跳 `/activate` 并清 keep-alive(**已在激活页时不再跳**,否则激活页上被 401 拦下的请求会把「跳到同一地址」变成整页重载,页面反复消失又出现,详见 [授权码](授权码.md)「激活页与 401 跳转」);blob 错误体解析回 JSON 弹错误通知。**所有接口反馈提示统一走 `web/src/utils/notify.js`**(基于 ElNotification,窗口右上角 macOS 通知风格:从右向左滑入、标题+摘要两行、超长内容「展开全部/收起」原地展开、新通知置顶、堆叠跟随高度变化重排、到时自动消失(长内容放宽到 10s);同时留痕到通知中心(`stores/notifications.js`,**只存 localStorage `dq-notify-history`,不落服务端/H2**,上限 100 条,被去重的重复通知不记录,刷新后保留;**导出成功通知额外携带 `exportPath`(落盘绝对路径),通知中心抽屉据此给历史导出通知渲染「打开文件 / 打开文件夹」操作**)——头部右侧铃铛按钮(`components/NotificationBell.vue`,无角标)点开右侧抽屉看历史通知(最新在前、带类型色点与时间,跨天带日期),抽屉内可「清除所有」、2s 内同内容去重),业务代码沿用 `ElMessage.success/error/warning/info(text[, options])` 调用形态、只改 import 来源,`options.title` 可自定义通知标题(默认「操作成功/失败」等)、`options.onClick` 挂点击回调(后台任务中心的完成通知据此「点击前往结果现场」);`ElMessageBox` 确认框仍直接用 element-plus。头部铃铛左侧另有**任务中心常驻入口**(列表图标按钮,任何时候可见,有活动任务时角标计数,tooltip 逐项一行式进度、无任务时提示暂无,点击打开 `BackgroundTasksDrawer`)与**后台任务指示器**(仅存在活动任务时渲染:旋转图标 + 单任务「推导/比对 · 阶段 百分比」/多任务「后台任务 ×N」,点击同样打开任务抽屉),数据源 `stores/backgroundTasks.js` 模块级单例跟踪器(1s 轮询推导/比对的 active 接口,终态即停,详见 [ER 关系推导](ER关系推导.md)「异步任务与轮询」;**App 挂载时的首轮拉取先读授权状态,未激活/已过期直接跳过**——否则激活页上必然的 401 会被拦截器变成整页重载死循环;本会话内激活成功后由 `dq-license-changed` 补一次起步;**受菜单门禁的 kind 按授权菜单裁剪**(`KIND_MENU` 只登记 compare:未开放 compare 菜单的实例不发起 `/compare-jobs/active`,避免每次启动打一发必 403 的探测;relation-infer 后端不按菜单校验,故不裁剪))
- 布局(App.vue):`/activate` 为全屏独立页不渲染框架;其余页面 = 左侧侧边栏(一级功能导航,App.vue 内定义;默认 200px,右缘手柄可拖拽调宽,最小 160px、最大视口 40%,存 `localStorage('dq-sidebar-width')`,可收起为 64px)+ 右侧(48px 头部[左侧浏览器式 返回/前进/刷新 按钮 + 当前一级功能名 + 三档主题切换,自动/浅色/深色,存 `localStorage('dq-theme')`] + 页签栏 + 主内容(`keep-alive` 缓存 20 个,key=`route.fullPath`+刷新戳))。返回/前进基于路由历史(`window.history.state` 的 back/forward),无可去方向置灰禁用;刷新为软刷新——递增刷新戳改变 keep-alive key 强制重挂载当前页重新拉数,不做整页 reload(避免丢失内存页签状态)。
- 侧边栏「数据源」为**可展开树**(el-sub-menu):子项「全部数据源」(→ 列表页)+ 各数据源(带 DbTypeIcon,点击直接进该数据源库列表;项右侧有编辑图标,**点击就地弹出该项的编辑框,不跳数据源页**——弹框组件 `DatasourceEditDialog` 由 App.vue 自己持有,侧边栏行与数据源页卡片同源同字段口径,分组候选由侧边栏现有数据聚合),设了分组的数据源先按分组成组——命名分组渲染为可折叠子菜单(文件夹图标+数量角标,下钻时自动展开所在分组),未分组平铺在最后;标题右侧 ⋮ 下拉提供「新增数据源 / 导入配置 / 导出配置(JSON)」。数据源列表由 App.vue 拉取 `/api/datasources`(进入数据源相关页、展开子菜单时刷新,失败静默维持旧列表);排序与主界面卡片一致——收藏的在前、同收藏按收藏时间倒序(共用 `utils/dsFavorites.js`,主界面切换收藏时经 `dq-ds-favorites-changed` 事件即时刷新);数据源页新增/编辑/删除/导入后经 `dq-ds-list-changed` 事件(`utils/dsListChanged.js`)通知侧边栏即时重拉,分组结构变更不等下次路由进入(编辑弹框保存时也广播该事件,故数据源页自己也会重拉卡片);列表限高 40vh 滚动,「全部数据源」固定不随列表滚动。
- 侧边栏「数据源」操作下拉通过 `tabState.pendingDsDialog`(stores/tabs.js)传递命令,数据源页消费后清空并打开对应对话框。**不用路由 query**——App.vue 的 keep-alive 以 `route.fullPath` 为 key,query 变化会导致组件重挂载、弹框状态丢失。**这个模块级标记只许激活态实例消费**(`Datasources.vue`):软刷新换 keep-alive key 后,旧实例仍留在缓存里(`isDeactivated=true`)但它的 watcher 照常触发,一旦让它抢先清空标记,弹窗就开在那个已停用的隐藏子树上——表现为「点 ⋮ 新增/导入/导出没反应」;因此 watcher 跳过停用实例,并在 `onActivated` 补一次消费(标记在本页未激活期间写入时,激活本身不会产生新的依赖变化)。同类「模块级待办标记 + 页面实例消费」的写法都要按这个口径处理。(侧边栏编辑图标原先也走这个模式,现已改为 App.vue 就地弹框,不再需要跨页传递。)
- 侧边栏高亮:`activeNav` 按路由前缀推导——`/datasources` 高亮「全部数据源」,`/datasources/:id/*` 高亮对应数据源项并自动展开树,`/scans*` 高亮「扫描记录」(任务域),其余一级页各自命中;`/license-admin` 仅 `status.admin && 授权码开放 license-admin 菜单` 显示入口。
- 页签栏 `v-if="tabState.tabs.length"`:「数据源」一级页不占页签,全部页签关闭后整条隐藏。
- **授权菜单控制**:侧边栏**所有一级菜单**(含「数据源」整棵与子项、「授权管理」)按 `/api/license/status` 的 `menus` 开放列表过滤(勾选即展示,不再区分基础/受控功能;旧后端无 menus 字段时按旧 features 推导兜底,详见 [授权码](授权码.md) 菜单列表);「授权管理」另需 `status.admin`。路由守卫按「路由前缀 → 菜单 key」映射(`routeMenuKey`,`MENU_ITEMS` 顺序即侧边栏顺序)拦截未开放菜单的直接 URL 访问并跳回首个开放菜单页(`firstGrantedHome`,兜底 `/datasources`);`/diagnostics` 未激活也放行(排错场景)不受此限;`/errors`(错误中心)是**普通受控菜单**(key `error-center`),未激活跳激活页、未开放菜单跳回首页。更换授权码成功后 `markActivated()` 广播 `dq-license-changed` 事件,App.vue 监听后整体刷新侧边栏(重取状态 + 数据源树);若当前页因新授权失去菜单权限(如正在授权管理页而新码未开放 license-admin)主动跳回首个开放菜单页

### 页签系统(`stores/tabs.js`)——理解页面关系的前提

> 「数据源」一级页(列表)由侧边栏导航直接切换,**不占页签**;数据源之外的其余一级功能页(扫描记录/标记统计/AI 统计/报告列表/抽样导出/ER 关系/SQL 控制台/运行日志/系统诊断/错误中心/授权管理)**各占一个固定页签**——侧边栏点击时已存在则定位、不存在则追加到最右侧;页签同时管理工作流下钻页。

| 页签 | key | 行为 |
|---|---|---|
| 数据源外一级功能页 | `page-{path}` | 可关闭;扫描记录/标记统计/AI 统计/报告列表/抽样导出/ER 关系/SQL 控制台/运行日志/系统诊断/错误中心/授权管理各占 1 个,标题固定 |
| 每数据源 1 个 | `ds-{id}` | 可关闭;库列表→表列表→扫描记录在**同一页签内下钻**,标题随路由动态变(由 `resolveTab` 推导) |
| 每扫描任务 1 个 | `scan-{jobId}` | 可关闭;**关闭时优先跳回其来源数据源页签**(`scanDsIds` 缓存),而非相邻页签 |
| (空态兜底) | — | 关闭最后一个页签后 `activeKey=''`,跳回 `/datasources`(侧边栏可重新下钻) |

### 路由守卫(`router/index.js`)

- 除 `/activate` 外每次导航先查 `GET /api/license/status`(Promise 缓存,并发共享);未激活/已过期 → `/activate`;激活成功后 `markActivated()` 更新缓存避免守卫重复查询。
- `/diagnostics`(系统诊断)跟 `/activate` 一样直接放行:排错场景常是授权问题本身。`/errors`(错误中心)不走这条豁免,按 `error-center` 菜单正常校验(后端 `POST /api/errors/report` 仍永远放行,采集不受菜单影响)。
- `/license-admin` 额外要求 `status.admin`,非管理员回 `/`。
- 懒加载 chunk/CSS 失败兜底(`router.onError`):前端重新构建后旧页面仍开着时,旧 hash 资源在新构建中不存在,vue-router 默认吞成未捕获 Promise(表现为「点按钮没反应」)——自动整页刷新一次换新资源;本会话(sessionStorage `dq-chunk-reload`)已刷新过仍失败则弹「请关闭窗口重新打开」,避免反复刷新。
- 各页包屑用 `Breadcrumb.vue`;页面回退统一用头栏的浏览器式返回/前进按钮(见「总体框架」布局)。

## 逐页面按钮逻辑

### 首页/数据源管理 `Datasources.vue`(`/datasources`)

卡片网格展示全部数据源;未设密码的卡片红色警示 + 禁用浏览。**每次切回页签都刷新**(`onActivated`)。工具栏带搜索框(匹配名称/主机/用户名/类型);卡片右上角星标为收藏(本地偏好,按 id 存 `localStorage('dq-ds-favorites')`),收藏的卡片排最前、同收藏按收藏时间倒序(后收藏的在前,逻辑在 `utils/dsFavorites.js`,与侧边栏共用)。

| 按钮/控件 | 触发行为 |
|---|---|
| 搜索框 | 前端过滤卡片(名称/主机/用户名/类型),无匹配显示空态 |
| 收藏星标 | 切换收藏 → 写 `localStorage('dq-ds-favorites')`,卡片收藏优先 + 收藏时间倒序排序 |
| 导出 | 默认全选 → 弹导出框(单选切换导出内容:连接配置 / 元数据缓存)→ `downloadFile('/api/datasources/export?ids=...' 或 '/api/datasources/metadata-export?ids=...')` 导出 JSON;侧边栏数据源 ⋮ 下拉「导出」同入口 |
| 导入 | 弹导入框(文件/粘贴两模式),支持 `.json`(连接配置 `dq-tool` / 元数据 `dq-tool-metadata`,后端按顶层 app 分发)/ Navicat `.ncx` / DataGrip 剪贴板;文件模式选中后先经 `confirmImportFile`(见贯穿性机制 9)识别确认(确认后返回识别结果对象);**元数据文件先进映射步骤**:`POST /datasources/metadata-transfer/preview` 预检,按连接身份自动匹配本机数据源并预填(无匹配默认「新建数据源」,可改选),确认后随 `mapping` 表单字段(文件数据源名 → 本机 id,0=新建)提交 `POST /datasources/import`;其余文件直接提交;展示 总数/成功/自动改名/失败原因/警告 |
| 新增/编辑 | 数据源编辑弹窗(独立组件 `DatasourceEditDialog.vue`,见通用组件,抽样导出页复用):DataGrip 风格,**常规/SSH隧道/库过滤/高级 4 页签**;编辑态秘密字段(密码/私钥/口令)一律不回填、留空=不修改;SQLSERVER 的 encrypt/trustServerCertificate/sslProtocol 三个连接参数在「高级」页签编辑(默认 true/true/TLSv1.1,兼容老版本 SQL Server),编辑打开时从已存 URL 剥离回填,保存/测试/拉库列表时先剥后拼回 URL;保存 `POST /datasources` 或 `PUT /datasources/:id`(后端同时把抽样导出的连接状态标记清零,回到「未检测」) |
| 测试连接 | `POST /datasources/test`,编辑态带 id,密码/SSH 秘密留空由服务端回落已存值(与 preview-databases 同一套 `mergeStoredCredentials`);结果不弹全局通知,按钮右侧显示状态图标(DataGrip 风格),悬停弹出详情(成功:DBMS/驱动名称与版本、Ping 毫秒、SSL、兼容模式;失败:错误消息;含 409 SSH 隧道失败),请求带 `_silent` 跳过拦截器 toast |
| 删除 | 二次确认 → `DELETE /datasources/:id` → 刷新 |
| 库过滤「加载库列表」 | 编辑态连接未改走 `GET .../databases?all=true&refresh=true`(为空回落 `/schemas?all=true&refresh=true`),**refresh=true 强制实时回源、不读本地缓存**(该按钮语义就是拉源库当前真实的库);源库不可达时后端降级返回缓存并打 `X-Dq-Cache-Fallback` 响应头,前端据此警告「当前展示的是本地缓存库列表」;否则 `POST /datasources/preview-databases` 按表单实时连接;保存 `PUT /datasources/:id/schema-filter`(勾选恰好等于默认业务库集合=不过滤;空名单=默认规则:全部业务库、排除系统库,见 [数据源](数据源.md)) |
| 卡片拖拽 | 原生 HTML5 drag & drop 把卡片拖到其他分组区块(分组头/卡片网格均可放置,折叠组的头也能接收)改分组 → `PUT /datasources/:id/group`(拖到「未分组」传 null),同组放置忽略;成功后整体重拉并通知侧边栏刷新 |

### 库列表 `Schemas.vue`(`/datasources/:id/schemas`)

表格展示库 + 每库最近扫描状态/进度/标记;有运行中任务时每 2s 轮询统计(标记接口失败保留旧数据)。
库/schema 清单走本地 H2 缓存(`meta_database`,与表/字段结构缓存同一套懒加载+覆盖语义):**缓存优先,切换网络连不上业务库时有缓存即可正常浏览**;缓存存全量,白名单在读取路径过滤(改白名单无需重建);首次访问或点「刷新」(`refresh=true`)才回源业务库并覆盖缓存。回源遇连接失败时后端**降级返回本地缓存**并在响应头带 `X-Dq-Cache-Fallback: true`,页面顶部显示「数据源当前不可达,正在展示本地缓存」告警(见 数据源.md「数据源不可达时降级读本地 H2 缓存」)。
SQL Server/Kingbase 多库场景:无数据库下拉,**始终跨库展示**,「库名」拆为**数据库 + 架构(Schema) 两列**——前端逐库拉取 schema/统计后按 数据库+架构 键合并,行内携带所属数据库,扫描/下钻/描述/报告导出均按行内 db 处理(报告导出按数据库分组逐库提交任务);搜索框同时匹配数据库名与架构名。其他方言仍是单列「库名(Schema)」。

### 统一下载封装 `utils/download.js`

所有「下载/导出」统一走 `downloadFile(apiPath)`(数据源导出、标记导出、扫描 Excel 导出;Word 报告落盘有产物,仍用 `save_report_as` 复制,见报告列表),两形态同一手感「直存 `<数据目录>/exports/` + 完成后打开文件/打开文件夹」:**桌面端**(tauri,`isTauri` 判断 `__TAURI_INTERNALS__`)`invoke save_download`,Rust GET 本地后端流式接口写盘;**浏览器 / jpackage `--app`** `POST /api/system/save-download`,后端**自调**目标导出接口(复用全部流式导出接口,零改动;Tauri 里 Rust 的同一角色)写盘。两形态文件名都以后端 `Content-Disposition` 为准、先写 `.part` 再 rename;后端生成整份导出才写出首字节,等待期间前端弹常驻「正在导出」;完成通知提供「打开文件 / 打开文件夹」按钮(导出路径经 `exportPath` 随通知记录留痕,通知中心抽屉里的同款历史通知也渲染这两个按钮,复用同一对 `openSavedFile`/`showSavedFolder` → `/api/system/open`、`/api/system/reveal`,后端把路径限在数据目录内;与用户确认:完成后**不自动弹文件管理器**,由用户点按钮打开)。错误响应经 axios 拦截器解析出 message 弹提示而非空白页——曾用 `window.open` 新开窗口,`--app` 会把新窗口甩给系统默认浏览器(另一个浏览器配置)且错误页空白、文件导不出来,2026-09 起废弃;下载类请求 `timeout: 0`,大文件慢速内网不受 30s 默认超时限制。

前端组装内容的文本下载(目前仅诊断报告)走 `downloadText(filename, text, mime)`:Blob + `a[download]`,浏览器与 Tauri webview 均可用。

## 贯穿性交互机制

1. **轮询纪律**:扫描相关页(库列表/表列表/扫描记录/扫描详情/报告列表;其中「扫描记录」含库内扫描记录页与全局扫描记录页)在存在 PENDING/RUNNING 任务时每 2s 轮询;`onDeactivated`/`onUnmounted` 停止、`onActivated` 恢复/刷新--靠 keep-alive 生命周期而非定时销毁。
2. **后端就绪轮询**(main.js):后端启动时先绑定端口提供静态页面(首页秒出),共享内核(H2 建表/迁移 + 中断恢复)随后完成;应用挂载前轮询 `/api/health`(200ms 间隔、60s 超时兜底),轮询到 200 才 mount——期间页面停留在 index.html 的启动占位,业务视图不会在就绪前挂载导致接口报错刷屏。**启动占位(2026-08 启动优化)**:品牌 logo + 三阶段步骤条(加载配置/启动服务/初始化数据),未就绪的 503 响应带 `stage` 字段(`StartupStage`),轮询时按阶段点亮"已过=绿、进行中=蓝呼吸"步骤,等待有动效反馈;就绪后 `#app` 被 Vue 替换,占位消失。**启动诊断面板(index.html 内联,2026-09)**:资源加载失败(脚本/样式)/页面脚本错误/服务超 20s 未就绪时,左下角自动弹出诊断面板,列出服务状态、已等待时长、问题记录(含失败资源 URL),支持一键复制——用户卡在启动页时截图或复制即可反馈,无需打开控制台;Vue 挂载后面板自动隐藏。**失败资源复核(2026-09)**:script/link 的 error 事件拿不到失败原因,诊断脚本对失败 URL 用 fetch 复核一次记录状态码,再与后端现场枚举的本构建资源清单 `/api/assets-manifest`(与 /api/health 同批放行就绪闸门/激活检查;打包运行枚举 fat jar 的 static/ 条目,dev 遍历 classpath 资源根)比对,直接在面板给出根因判定——在清单内但仍拿不到 = 疑似杀毒软件/代理拦截,不在清单内 = 入口与后端版本错配,用户一张截图即可区分。**入口错配自愈(2026-09)**:入口 html 是旧构建(浏览器会话恢复/升级重启窗口期拿到的陈旧副本)而后端已是新构建时,旧 hash 入口 js/css 404 会永远卡死启动页——诊断脚本在「资源加载失败 且 /api/health 已 200」时判定入口与后端错配,整页强制刷新一次拿匹配的新入口(sessionStorage `dq-boot-reload` 计数防死循环,挂载成功后清除;包本身损坏刷新无效,仍交给诊断面板展示);入口 html 同时改发 `Cache-Control: no-store` 从源头杜绝旧副本(见 构建运行与测试 静态资源缓存策略)。
3. **二次确认**:所有删除、取消都过 `ElMessageBox.confirm`;扫描入口统一走共享扫描对话框组件 `ScanDialog.vue`(表列表/库列表/扫描详情三处复用:单表定死 `fixedTable`、勾选 `selectedTables`、整库多目标 `targets` 逐库提交不跳转;字段/提交/AI 可用性校验/提交后跳转均内聚在组件内)。
4. **弹窗禁 Esc 关闭**:所有 `el-dialog` 统一带 `:close-on-press-escape="false"`、所有 `ElMessageBox` 调用带 `closeOnPressEscape: false`——弹窗只能点右上角叉叉或底部按钮关闭,任何键盘事件不得关弹窗;新增弹窗时必须遵守。
5. **只读筛选模式**:外部带 `tagId` 进入表列表时,写操作(扫描/打标/AI 描述/生成描述)全部隐藏,顶部 alert 一键清除恢复。
6. **安全边界**:编辑态秘密字段不回填;401 全局踢回激活页;导出文件含加密密码有警示文案;`/api/license/*` 与 `/api/heartbeat` 不参与授权拦截。
7. **路由-页签联动**:页签标题由 `resolveTab(route)` 动态推导,页签 key 决定关闭后的去向(扫描页签 → 来源数据源页签)。
8. **数据源名兜底解析**:库/表/扫描等页面在面包屑与页签标题中展示数据源名,来源优先级为 URL `?name=` → 内存缓存 `dsNames` → `ensureDsName(id)`(`stores/tabs.js`)。后者按 id 从 `/datasources` 列表补全并回写缓存(同 id 并发只发一次请求,失败静默返回空串,维持「数据源 ${id}」兜底显示);刷新/直达 URL 无 `?name=` 时,由页面挂载/激活时调用 `ensureDsName` 恢复真名并 `syncTab` 刷新页签标题。
9. **导入文件识别确认**(`utils/importFileIdentify.js`):三个文件导入入口(数据源/扫描记录/标记与描述)选中文件后一律先走 `confirmImportFile(file, currentFeature)`——读文件文本时 UTF-8 优先、失败按 GBK 兜底(客户可能用记事本另存为 ANSI,与服务端 `TransferJson` 口径一致),按内容识别文件归属(三种 JSON 导出靠顶层 `app` 字段 `dq-tool` / `dq-tool-scans` / `dq-tool-annotations` 区分,Navicat `.ncx` 与 DataGrip 剪贴板按 XML 特征),弹窗告知"识别到该文件是 XX(内容摘要)":归属当前功能则等用户「确认导入/取消」;不属于当前功能、版本不兼容或无法识别时弹提示阻断(拿错文件时指路到正确入口),不发请求。新增导入入口时必须接入。
10. **下载/导出双形态兼容**(`utils/download.js`):**所有**下载、导出入口必须经 `downloadFile(apiPath)`(后端流式接口)/ `downloadText`(前端组装文本)/ `downloadDataUrl`(画布图片),**禁止裸 `<a href="/api/...">` 点击、`window.location` 赋值、裸 `window.open('/api/...')`**。原因:产品有两种运行形态——浏览器 / jpackage `--app` 模式(页面与 API 同源 `/api`,整页跳转与下载靠服务端种的 Cookie 过门禁)与 Tauri 套壳(webview 从本地 `frontendDist` 直载,页面源是 `tauri://localhost`,API 在 `http://127.0.0.1:<动态端口>` 跨域,门禁走 token):相对路径 `/api/...` 在 Tauri 下会被解析到 `tauri://` 源,点击即把整个 webview 导航走、SPA 崩溃重载——2026-09 差异明细「导出比对报告」事故(点击后菜单丢失、页面被甩回比对列表)就是全项目唯一一处裸 `<a>` 漏网所致。`downloadFile` 已分形态处理:Tauri 走 Rust `save_download` 命令直存数据目录 `exports/`(GET 带 token 流式写盘,文件名以 Content-Disposition 为准,先写 `.part` 再 rename),浏览器 / jpackage `--app` 走 `POST /api/system/save-download` 由后端自调目标导出接口直存(同目录同口径;错误响应体解析后随 409 带 message,拦截器统一弹提示)。新增下载入口时别无选择,且必须在 Tauri 套壳下验证一次(浏览器模式通过不代表 Tauri 可用)。
11. **HTML5 拖放与 Tauri 宿主覆盖**(2026-09):前端多处依赖原生 HTML5 拖放——`el-upload` 拖拽区(比对任务批量导入、抽样导出导入/重新导入、数据源导入)、对象管理 `el-tree` 拖动目录/挂载表移动与关系表拖到表节点、数据源卡片拖到分组。Windows 上 Tauri 默认开启自带拖放处理器,会把 WebView2 的 OLE drop target 换成只认文件(`CF_HDROP`)的实现,非文件拖拽一律被拒(`DROPEFFECT_NONE`)、文件拖拽则只发 Tauri 的 `tauri://drag-drop` 事件而不进页面——**浏览器 / jpackage 形态没有这层宿主覆盖,只测浏览器永远发现不了**。已在 Rust 侧关闭该处理器(`.disable_drag_drop_handler()` 于窗口构建链,见 [tauri/AGENTS.md](../../tauri/AGENTS.md)「必须关闭 Tauri 拖放处理器」):新增或改动依赖拖放的交互后,必须在 Tauri(Windows)形态实测一次;G6 画布(ER 图/字段映射)走 pointer 事件,不受该机制影响。
