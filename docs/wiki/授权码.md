# 授权码

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。本文覆盖离线授权码体系与授权码管理;安全侧约束另见 [代码约定与安全](代码约定与安全.md)。

- 离线 Ed25519 签名授权码(payload 为 客户名|有效期|软件版本|server_url|username|sid|签发时间戳|旧功能段|菜单列表|免鉴权标记,`expires=permanent` 可签发永久授权,兼容两段/六段/七段/八段旧格式),未激活/过期时除 `/api/license/**` 外所有接口 401,前端强制跳激活页
- 签发用 `scripts/LicenseKeygen.java`(**交互式**:依次提示输入私钥/客户/有效期/版本/扩展字段/菜单列表/免鉴权,回车用默认值——客户默认「内部测试」、私钥默认 `license-private.key`、有效期默认 30 天后(可输入 `permanent` 永久)、版本默认取根目录 VERSION 文件去 `0.` 前缀、菜单回车=全部菜单、免鉴权默认 false;或 `make license` 快捷命令),公钥单独存文件 `server/src/main/resources/license-public.key`,`application.yml` 的 `dq.license.public-key-file` 只存文件路径(`classpath:` 前缀读 jar 内资源,否则按文件系统路径,兼容旧的内联 `dq.license.public-key`),私钥 `license-private.key` 不入库
- **授权码管理(仅管理员)**:yml 配 `dq.license.private-key-file` 指向签发私钥即为管理员实例,开放 `/license-admin` 页与 `/api/license/admin/codes` 接口(生成/留档 `license_record` 表/查看含完整码/删除,不可编辑;SID 未填时服务端自动生成 UUID 去横杠,页面不再提供输入框;删除仅删留档,离线方案无法吊销已分发码;非管理员访问 403 `LicenseAdminRequiredException`),管理端点在 /api/license 前缀下不被激活拦截(管理员实例可不激活使用);签发对话框加宽(1040px)平铺 16 个菜单复选框,带全选(半选态)
- 软件版本号构建期由 gradle 去 `0.` 前缀注入 `app-version.txt`(与安装包版本一致),状态接口透出 `appVersion`/`admin`,首页底部页脚显示

## 菜单列表(10 段新格式)

授权码 payload 第 9 段为**逗号分隔的菜单 key 列表**,第 10 段为免鉴权标记(`true`/`false`)——**勾选即客户实例侧边栏可见,不再区分基础/受控功能**(10 段新格式;2/6/7/8 段旧格式无这两段)。

菜单定义见 `common/.../license/LicenseMenu.kt`(16 项,key 与前端一级路由一致):

| key | 菜单 | key | 菜单 |
|---|---|---|---|
| `datasource` | 数据源 | `object-manage` | 对象管理 |
| `dashboard` | 扫描记录 | `sql-console` | SQL 控制台 |
| `tags` | 标记统计 | `lan-share` | 局域网共享 |
| `manual-collects` | 人工采集 | `ai-usage` | 模型用量统计 |
| `report-exports` | 报告列表 | `settings` | 系统设置 |
| `sample-exports` | 抽样导出 | `diagnostics` | 系统诊断 |
| `compare` | 数据比对 | `logs` | 运行日志 |
| `relations` | ER 关系 | `license-admin` | 授权管理 |

规则:

- 新格式授权码**按菜单段原样开放**(新格式无隐式基础集):勾选才展示,未勾选的前端隐藏入口、路由守卫拦截、后端菜单校验接口 403
- **旧格式授权码(无菜单段)按旧功能段推导**(`LicenseMenu.granted`):全部菜单除 数据比对/授权管理 外默认开放,两者按旧功能段是否显式包含(`compare`/`license_admin`)恢复——与旧版「基础业务功能恒有 + 受控功能显式包含」的行为完全一致,已分发的旧码不受影响
- 签发请求(`LicenseGenerateRequest`)显式传 `menus` 按它签发;未传 `menus` 但传旧 `features` 时按旧功能列表推导(旧版签发端兼容);两者皆无则默认开放除 数据比对/授权管理 外的全部菜单;未知 key 忽略并按枚举声明顺序规范化
- 状态接口 `/api/license/status` 的 `menus` 字段返回已开放菜单 key 列表(`features` 字段已移除;前端对旧后端按 features 推导兜底);`bypassAuth` 字段透出免鉴权标记是否生效
- 签发对话框默认**全勾**(客户实例菜单全开放),可全不选/部分勾选

### 免接口鉴权(演示用)

授权码第 10 段 `bypassAuth=true` 时,该实例**所有请求跳过 `dq.access-token` 门禁校验**(业务接口、页面路由、未匹配路径都不再要求令牌),用于演示/截图场景:

- 仅**已激活未过期**的免鉴权授权码生效(`LicenseStatusView.bypassAuth = !expired && payload.bypassAuth`;过期/未激活一律按不豁免)
- 生效判断在 WebServer 访问管控 `before` 钩子里短路(`licenseService.isAuthBypassed()`,内部对异常按 false 处理,宁严勿松),AccessGuard 的静态豁免清单保持不变
- 免鉴权只豁免**访问令牌门禁**;授权激活校验(`/api/**` 须已激活未过期)不受影响

### 后端拦截

`WebServer.registerRoutes` 的 `beforeMatched("/api/*")` 在激活校验后追加菜单校验:

- `/api/license/admin/**` → `licenseService.checkMenu(LicenseMenu.LICENSE_ADMIN, requireActive=false)`:管理员实例未激活直接放行(可不激活使用),已激活则要求授权码开放 `license-admin` 菜单;过期仍拦截
- `/api/compare-jobs/**` → `licenseService.checkMenu(LicenseMenu.COMPARE)`:要求已激活且授权码开放 `compare` 菜单,未授权 403 `LicenseMenuRequiredException`
- 其余菜单不做接口级校验,由前端隐藏入口 + 路由守卫控制

### 前端入口控制

- 状态接口 `menus` 供前端判断:侧边栏**所有一级菜单**(含「数据源」整棵与子项、授权管理)按开放列表过滤;`/license-admin` 路由需 `admin && menus 含 license-admin`;其余菜单页直接输入 URL 由路由守卫按「路由前缀 → 菜单 key」映射(`routeMenuKey`)拦回首个开放菜单页
- 更换授权码成功后 `dq-license-changed` 广播,App.vue 重取状态刷新侧边栏;当前页因新授权失去菜单权限时主动跳回首个开放菜单页
- 未授权菜单前端隐藏入口 + 路由守卫拦截直接输入 URL;数据比对等后端另有 403 兜底防绕过

### 留档

`license_record` 表(V6 建表、V12 加旧功能段、V51 加 `menus`/`bypass_auth`)留档每次签发:新记录存菜单段与免鉴权标记,旧记录(`menus=NULL`)在列表视图按旧功能段推导菜单展示,与新码口径一致。
