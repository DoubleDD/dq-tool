# 错误中心(统一错误收集)

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。
> 一级页面「错误中心」(`/errors`,侧边栏入口),把**前端、后端、数据库、后台任务、启动期**产生的错误
> 统一采集进 H2,按指纹聚合后可筛选、可查看完整堆栈、可标记已处理/已忽略、可导出给开发。
> 与「运行日志」(`/logs`,全量实时流)和「系统诊断」(`/diagnostics`,一页式环境/连通性报告)的分工:
> **看全量日志去运行日志,判断环境与连通去系统诊断,查"到底哪里报错了"来错误中心**。

## 页面与 API

| 入口 | 说明 |
|---|---|
| `GET /api/errors` | 分页列表(筛选:`source`/`level`/`status`/`keyword`/`from`/`to`,分页 `page`/`size`) |
| `GET /api/errors/stats` | 统计卡片:总数/今日有发生/按来源/按级别 + `dropped`/`spoolPending` 采集健康度(响应仍带 `open`,页面不展示) |
| `GET /api/errors/{id}` | 单条详情(含最近一次的完整堆栈与上下文) |
| `POST /api/errors/report` | 前端错误批量上报(单次最多 50 条,字段超长截断,200ms 限流);**不校验激活与菜单,永远放行** |
| `POST /api/errors/clear` | 按当前筛选条件清空(条件全空 = 清空全部) |
| `POST /api/errors/purge` | 按天数手动清理 |
| `GET /api/errors/export` | 导出 Markdown/JSON(最多 500 条):带 `ids=1,2,3` 导出**所选行**(忽略筛选,非法 id 静默忽略);不带 `ids` 时沿用列表筛选条件导出全部匹配项 |
| `PUT /api/errors/{id}/status`、`POST /api/errors/batch-status`、`DELETE /api/errors/{id}` | **保留但页面不再使用**:产品定位为纯查看排错,不再做错误处置;`status`/`note` 列随 V56 已落地(迁移文件已应用,不删列),接口保留供外部按需调用 |

- 页面:`web/src/views/Errors.vue`;内核:`common` 的 `ErrorCenterService` / `ErrorRepository`(表 `error_record`,V56);
  server 壳层:`ErrorCenterController`(端点)、`ErrorCaptureAppender`(Logback 采集)、`ErrorCenterHolder`(静态上报出口)。
- **授权口径(双轨)**:页面是**授权码独立菜单 `error-center`**(`LicenseMenu.ERROR_CENTER`,签发对话框默认不勾选、可单独授权/屏蔽,`/errors` 与其它受控菜单一样过守卫)——
  **查看/统计/导出**接口 `licenseService.checkMenu(ERROR_CENTER)` 未开放即 403;
  但 **`POST /api/errors/report`(前端上报)永远放行**:不校验激活也不校验菜单。采集是基础设施,若跟着菜单一起被拦,
  未开放该菜单的实例前端错误会 403 静默丢失 —— 而"错误收不到"正是本系统要解决的问题。
  签发/留档/列表见 [授权码](授权码.md)。

## 采集覆盖矩阵

| 来源(`source`) | 采集点 | 说明 |
|---|---|---|
| `FRONTEND` | `web/src/utils/errorCapture.js` | `window.onerror`(含资源加载失败)、`unhandledrejection`、Vue `app.config.errorHandler`、`console.error` 包装、axios 4xx/5xx/网络错误 |
| `BACKEND` | `ErrorCaptureAppender`(挂 root logger) | ERROR 级别全收;WARN 仅当带异常时才收(降级提醒类 warn 不进错误中心) |
| `DATABASE` | 同上 | 异常链中任一环是 `SQLException`(业务库/H2)即归为数据库错误;`WebServer` 的 `SQLException` → 502 分支同样落入 |
| `STARTUP` | `DqApplication` | 启动失败(含内核初始化异常)、未捕获线程异常(默认处理器) |
| `TASK` | 预留 | 后台任务异常若已 `log.error`/`log.warn(msg, e)` 会以 `BACKEND` 入库;后续可按任务类型再细分 |

内部 logger `dq.error-center.internal`(采集自身故障日志)被采集器**显式跳过**,避免"采集失败 → 记日志 → 再采集"的自噬递归。

## 聚合口径(指纹)

`util/ErrorFingerprint` 计算 `SHA-256(source | kind | 归一化消息 | 首个业务栈帧)`:

- 归一化:引号字面量 → `?`、UUID → `<uuid>`、十六进制/长哈希 → `0x…`、数字 → `n`、空白压缩;
- 栈帧取第一条 `com.example.dq` 的 `at` 行并去掉行号 —— 行号/参数变化不会分裂记录,不同代码位置不会错误合并。

同一指纹只占一行:`occurrences` 累加、`last_seen` 刷新、`message`/`detail`/`context` 保留**最近一次**;
`first_seen` 不随新发生次数改变(新库记录固定为 `OPEN`,页面不做处置、不再变更)。occurrences 与指纹在页面详情里可见。

## 可靠性设计

- **不阻塞调用线程**:`ErrorCenterService.record()` 只入有界队列(2000),单守护线程 `dq-error-writer` 批量 upsert;
- **启动期不丢**:内核建表/迁移完成前(`markReady()` 之前),事件同步追加到 `logs/error-spool.jsonl`(JSON Lines,
  上限 20MB);`initDatabase()` 末尾就绪时回灌入库并删除文件 —— 启动失败/崩溃前的错误重启后仍可见(页面统计卡会提示 `spoolPending`);
- **写库失败兜底**:批量 upsert 失败的条目同样落 spool,并累加 `dropped` 计数;采集本身任何异常只写内部 debug 日志,绝不上抛;
- **保留策略**:默认保留 30 天、单表上限 2 万条(超出删最旧),就绪时执行一次,页面「清理」可手动按天数清理;
  可用 `application.yml` 的 `dq.error.retention-days` / `dq.error.max-records` 调整。

## 前端防刷屏

- 同指纹 3s 窗口内只上报一次;本地队列攒批(满 10 条或 1s)合并发送,单批最多 50 条,队列上限 50 条;
- 上报请求失败静默丢弃(不重试、不再报错,避免递归);
- 明确噪音直接忽略:`ResizeObserver loop`、vue-router 重复导航、`Script error.`;
- 状态类响应不算缺陷:401(授权失效,由跳激活页处理)与 503(内核就绪前的启动状态)不上报。

## 敏感信息边界

- 上报内容一律按不可信输入处理:来源固定为 `FRONTEND`(不采信客户端),字段超长截断,体积/条数设上限,并有 200ms 限流;
- 上下文只含页面路由、地址、浏览器 UA、接口路径与状态码、响应 message;**不含任何访问令牌与密码**;
- 后端堆栈按 Logback 原样采集,可能包含 JDBC URL 与文件路径(排错必需;本工具仅内网单机部署,可接受)。

## 页面能力(只读排错)

- **不做错误处置**:页面不提供标记已处理/已忽略、处理备注、删除等操作(产品定位是"任何地方的错误都能被看到并定位",不是工单系统);保留数据维护入口——按当前筛选清空、按天数清理(30 天/7 天),导出 Markdown / JSON;
- 列表:按来源/级别/时间范围/关键词筛选、自动刷新(5s)可开关、分页;**不做统计展示**(总数/按来源/趋势等一律不出现);`GET /api/errors/stats` 仍会被调用,但只为「采集健康度」——仅当 `spoolPending` 或 `dropped` 非 0(采集/落库出问题)时在筛选行上方出现一条黄色提示,正常时不占位;
- 详情抽屉:来源/级别/类型/累计次数/首次与最近发生/版本/logger/线程/位置/指纹 + 完整消息、上下文(页面、地址、接口、状态码、响应 message、浏览器 UA)、完整堆栈,一键「复制详情」便于贴给开发;
- **展示层百分号解码**:前端路由/接口地址的查询串是编码过的(`?name=%E4%BB%BB%E5%8A%A1` → `?name=任务管理`),直接展示读不了 —— 列表「位置」、详情「位置」、详情「上下文」、复制详情与导出的 Markdown 都在**展示时**解码(`Errors.vue` 的 `decodeUrlText` 与 `ErrorCenterController.decodePercent`,同一口径):
  - 只在确实含 `%XX` 时解码;解码失败(裸 `%` 等非法序列)原样返回,绝不让脏数据让页面报错;
  - **不把 `+` 当空格**(用 `decodeURIComponent` / 先转义 `+` 再 `URLDecoder` 的语义,保持路径原义);
  - **数据库、JSON 导出与接口响应始终是原始编码值**(诊断记录保持忠实,需要复现请求时可直接用);插入新数据不受影响,已收集的历史记录刷新页面即可见可读中文。
- 数据库列 `status`/`note` 与对应接口保留(见上表说明),页面不再读写。
