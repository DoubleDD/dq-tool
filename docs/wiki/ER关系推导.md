# ER 关系推导

> 厂商建表不规范(无外键约束、字段命名混乱),常规数据库工具无法生成 ER 图;本功能通过程序逻辑推导表间关联(字段名匹配 + 大模型语义匹配 + 值交集/基数验证),经人工确认后在前端以标准 ER 图(乌鸦脚)展示。政府项目验收刚需。

## 术语

| 术语 | 定义 |
| --- | --- |
| **锚点表 / 锚点字段** | 用户选定的一张表和其中若干字段,作为一轮推导的出发点。锚点字段即「候选关联键」——用户凭业务知识选定,程序不做噪音过滤,选什么用什么 |
| **候选关联** | 程序推导出来、未经人工确认的表间关系(status=CANDIDATE) |
| **确认关联** | 经人工核准的权威关系(status=CONFIRMED);全库总图只基于确认关联绘制 |
| **否决关联** | 人工判定为误报的关系(status=REJECTED);入库保存不进图,再推导时不跳过——重新验证,命中则回炉为候选(同 id 整行刷新,含方向翻转) |
| **孤儿表** | 全库总图中没有任何确认关联的表 |
| **全库总图** | 全部确认关联的并集绘制出的 ER 图;不是实时推导的结果 |
| **轻量值交集验证** | 对已配对的候选字段对,两端各取最多 1000 个 DISTINCT 值求交集比例,作为置信度的核心证据。是值集匹配的「验证形态」而非「发现形态」 |

## 推导流程

用户在对话框选锚点字段(主键字段默认勾选)→ 提交 `POST /api/relation-infer` → 异步任务逐阶段推进:

1. **双通道匹配**:
   - **名字匹配**:读整库字段缓存(`meta_schema_column`,未就绪则实时拉取并回填),忽略大小写命中,排除锚点表自身。每个锚点字段的**搜索名集合 = 本名 + 映射名**——映射名是用户手填的、其他表中引用该字段的常见字段名(如 `id` → `work_order_id`/`workOrderId`,解决关联表命名不一致问题),trim/去空/忽略大小写去重后任一命中即候选;**`aliasOnly=true`(对话框「只用别名匹配」开关)只对填了映射名的字段生效**——这些字段搜索名集合只含映射名,本名不参与(避免 `id` 等通用名全库误命中);**未填映射名的锚点字段不受该开关影响,仍按本名搜索**(无别名可依赖,不因开关静默退出);经映射名命中的关系 remark 注明「经映射字段名 xx 命中」(xx=命中用的映射名,本名命中不加),另一端字段存其他表中的实际字段名(保留真实大小写)。名字匹配阶段记 info 日志:字段清单来源(缓存/实时拉取)与规模、各搜索名命中明细(表.字段清单,前 30 条)、已存在/重复对跳过数、超上限丢弃数
   - **数据源不可达降级**(与元数据浏览同口径,`util/ConnectionFailureClassifier` 判定连接级失败):回源取字段清单失败时**写数据源 `conn_status/conn_kind` 标记**(数据源页红标),并**降级读本地 `meta_schema_column` 缓存推导**(可能只有部分表的 per-table 缓存,按现有缓存尽力而为),记 error 日志;**此时验证阶段不再尝试连接**(省一次连接池超时等待,如 30s),值交集/判重 SQL 全部跳过,候选按「未验证」入库(交集率/置信度留空,基数只信 `meta_index` 缓存,remark 注明「数据源连接不可达…待恢复后复核」),并在任务附注(`relation_infer_job.error`)**说明本轮为缓存降级**、对话框「推导完成」阶段以警示条展示。**已标记不可达 + 实测在 5 分钟新鲜窗口内**(`RelationInferService.KNOWN_DOWN_TTL`,`conn_checked_at` 判定)时本轮**连连接都不取**:不管字段缓存是否就绪都直接读缓存推导、验证阶段也不连(断网期间反复推导零等待);超窗后重新实测一次并刷新标记时间,**标记不会永久生效**(恢复后最多 TTL 自动恢复),编辑数据源清零标记后立即重测;`conn_checked_at` 缺失按过期处理,宁可实测一次。缓存一张都没有则任务照旧判失败(实测路径 error 日志带堆栈;窗口内路径给可操作提示「请恢复网络后重试,或先在数据源页刷新元数据」)。回源成功时此前 ERROR 标记自愈为 OK;非连接类异常(如无权限读某 schema)不降级,避免掩盖真实错误
   - **语义匹配**(可选,需已配置大模型):两阶段、原料逐级回退——
     - 阶段一·表级粗筛:锚点表对全库表分批(每批 100 张)发 LLM 筛相关表;每张表**有 AI 表描述(`table_doc.description`)用描述、无描述回退表注释、两者都无则不进 prompt**(仍可被名字匹配命中)
     - 阶段二·字段级精判:对粗筛出的每张表,把字段名+类型+注释与锚点字段逐表发 LLM 定字段对应;字段无注释的不进 prompt;锚点字段带映射名时该行追加「(在其他表中常见名: …)」提示
2. **合并去重**:两通道候选按方向无关字段对合并,同一字段对 source 优先 NAME_MATCH;已确认/候选对已存在则不重复验证/插入(已确认关系不被降级);**已否决对不跳过**——重新验证,命中则回炉为 CANDIDATE(同 id 整行刷新,按最新推导修正方向/基数/置信度,见 `TableRelationRepository.upsertDerived`)
3. **轻量值交集验证**:两端各 `distinctSampleSql`(≤1000 个 DISTINCT 非 NULL 值),值统一 `toString().trim()` 后求交集率(= 交集数/较小样本数,规避 NUMBER/VARCHAR 类型差);**任一侧样本为空(空表/字段全 NULL)不剔除**——空库也要能产出候选建 ER 图:交集率/置信度留空,remark 注明「样本为空…待有数据后复核」;交集 0% 只降置信不否决
4. **基数验证**:配对字段被某侧唯一索引/主键单列覆盖时直接定「一」侧短路(读 `meta_index` 缓存,免跑聚合);否则 `hasDuplicateSql` 判重(**样本为空时不跑**——空表无重复是假象,只信索引缓存)。两端唯一=1:1,一端唯一=1:N(one 侧存唯一方),两端重复=**疑似多对多**(标 remark「两端字段均存在重复值,疑似多对多,待人工裁决」,图上红色边);**空样本且两端均无索引佐证时暂按锚点侧为「一」存 1:N**(remark 注明,待人工裁决)
5. **置信度**:交集率 ≥80%=高,>0=中,=0=低
6. **防护**:单轮候选对上限 200(超出截断并记 warn 日志);所有验证 SQL 串行执行,单条超时沿用分段扫描口径;候选全部落 `table_relation` 三态

方向归一化:1:1 与疑似多对多方向无语义,按(表名,字段名)字典序小者入 one 侧,保证同一关系重复推导命中唯一键、幂等 upsert。

## 三处入口

- **表列表页(`Tables.vue`)行内「推导关联」**:弹 `RelationInferDialog`(预选当前数据源+库+schema+该表)
- **侧边栏「ER 关系」**(路由 `/relations`,页面 `RelationGraph.vue`,占 1 个固定页签):全库总图 + 星型图 + 手动补充
- **字段明细页(`TableDetail.vue`)**:「ER 关系」页签(本表星型图),页签工具栏带「推导关联」(预选本表)与「手动补充」按钮

两处共用同一实现 `utils/erGraphExport.js` 的 `exportErGraphExcel`,口径如下:

- **行口径**:图内每张表 × 该表作为关系端点的去重级联字段(一表多个关联字段出多行,孤儿表出一行且级联字段留空);边集合即当前图数据(全库总图仅确认边,星型图恒含候选)
- **库名/模式按数据库类型取值**:多库方言(SQL Server/Kingbase)库名=所选数据库、模式=schema;MySQL/OceanBase 只有库没有模式,路由 schema 参数实为 catalog(库名),模式留空;PostgreSQL/瀚高库名=JDBC URL 上的数据库名、模式=schema;Oracle 库名=URL 上的 SID/服务名、模式=schema;达梦等无库概念方言库名留空、仅模式。数据源 dbType/jdbcUrl 由 `exportErGraphExcel` 内部按 dsId 拉 `/datasources` 解析,调用方不再传 dsName
- **数据量**:与表列表页同口径——非采样的最新 DONE 扫描精确行数优先(`GET .../latest-scan-jobs`),否则回退元数据估算行数(`GET .../tables` 的 estRows);两者都无则留空
- **级联字段名称** = 字段注释,取自整库字段清单(与「全部字段」档同一接口,经 `loadColumnsMap`/`loadErColumnsMap` 按库缓存,忽略大小写匹配)
- **生成方式**:纯前端组装表头+行,走通用列表导出通道(`exportListToExcel` → `POST /api/list-exports` + token 下载),不新增专用后端导出接口

## 导出 .drawio

ER 图可一键导出为 draw.io 格式文件(`.drawio`),用 draw.io 桌面版(免费、可离线安装,内网环境可用)或在线版打开继续编辑/定稿/导 PNG,补足应用内「布局不持久化、无图片导出」的短板;不内嵌 drawio 编辑器(自托管静态资源约 51MB,体积代价不值)。

- **入口**:ER 关系页工具栏「导出 drawio」(全库总图/星型图皆可)+ 字段明细页「ER 关系」页签(本表星型图);文件名 `ER 总图-<schema>.drawio` / `ER 星型图-<schema>-<表>.drawio`
- **所见即所得**:导出内容 = 当前画布口径——显示档位(仅表名/关联字段/全部字段)、候选边(仅星型图含,全库总图恒为确认边)、G6 实测布局坐标(拖动后的实时位置)、各节点展开态(折叠的节点超 `maxFieldRows` 行记为「+N 个字段」行,已展开的节点全量导出,与画布一致)
- **生成方式**:纯前端拼装(`web/src/utils/drawioExport.js`,`buildDrawioXml` 纯函数 + `downloadDrawio` 下载),复用诊断报告 `downloadText` 下载通道(浏览器 Blob / Tauri 原生保存双端可用);画布组件 `RelationGraphCanvas` 经 `defineExpose` 暴露 `exportData()`(节点表名/注释/布局中心/字段行 + 原始关系边,行集合复用画布 `nodeFields` 保证与渲染一致);不新增后端 API、不走网络
- **drawio 结构**:表节点 = drawio 原生 ER 表(`shape=table` + `tableRow` + `partialRectangle`,表头中文名为主标题、英文表名小字在下(与画布节点表头一致),关联字段加粗蓝色高亮),打开后可增删行、把连线拖到具体字段行;关系边 = `entityRelationEdgeStyle` + 乌鸦脚端标记(1:1 双端竖杠 / 1:N 一端竖杠一端鸦脚 / 疑似多对多双端鸦脚),边标签为基数(1:1 / 1:N / M:N(疑似)),颜色沿用画布语义(确认=蓝实线 / 候选=灰虚线 / 疑似=红实线);配色固定中性值不随应用亮暗主题
- **已知简化**:边连接点交给 drawio 正交路由自动选取(不预置 exitX/entryX 锚到字段行);同表对多条平行边可能路由重叠,由用户在 drawio 中手动调整;**不做反向导入**(.drawio → table_relation 不解析,避免反推四元组的易碎性);画布字段行的字段注释(hover 看全文)不进 drawio 导出——drawio 单元格内超长无省略号截断能力,导出行保持「字段名+类型」,避免长注释撑破行高
- **坐标兜底**:节点布局坐标取不到(未完成布局)时按 5 列网格兜底排布;端点表不在节点集的边跳过

## API(路由在 WebServer,handler 在 RelationController)

| 方法/路径 | 说明 |
|---|---|
| `POST /api/relation-infer` | 提交一轮推导 `{datasourceId, dbName, schemaName, table, fields[], useSemantic, aliasOnly}`;fields 项为 `{name, aliases[]}`(name=锚点字段名,aliases=用户手填映射名,可空);`aliasOnly`(缺省 false,向后兼容)=true 时**填了映射名的字段**名字匹配只用映射名、不用本名,未填映射名的字段不受影响仍按本名;返回 `{jobId}`;异步执行 |
| `GET /api/relation-infer-jobs` | 按库查询推导任务列表(前端轮询/历史) |
| `GET /api/relation-infer-jobs/{id}` | 任务详情(fields/stage/totalSteps/doneSteps/foundCount/error) |
| `GET /api/relations` | 关系列表(`status`/`table` 可选过滤) |
| `POST /api/relations` | 手动补充关系 `{oneTable, oneColumn, manyTable, manyColumn, cardinality, remark?}`:source=MANUAL 直接 CONFIRMED;命中唯一键转 CONFIRMED 返回原 id,响应 `{id, existing}` |
| `POST /api/relations/{id}/confirm` | 确认(候选/否决均可转确认) |
| `POST /api/relations/{id}/reject` | 否决(候选/确认均可转否决;否决对再推导时重新验证,命中回炉为候选) |
| `DELETE /api/relations/{id}` | 删除(任意状态,误删可重新推导找回) |
| `POST /api/relations/batch-confirm` | 批量确认(body `{ids[]}`,单次上限 1000;同单条口径状态互转),返回 `{ok, updated}`(updated=实际影响数,不存在的 id 忽略) |
| `POST /api/relations/batch-reject` | 批量否决(同上) |
| `POST /api/relations/batch-delete` | 批量删除(任意状态,误删可重新推导找回),返回 `{ok, updated}` |
| `GET /api/relation-graph` | 图数据:`table` 空=全库总图(CONFIRMED 边+孤儿表,`includeCandidate` 加候选边);非空=该表星型(恒含 CONFIRMED+CANDIDATE 边,不含 REJECTED) |

## 库表(V35__table_relation.sql)

无外键(同 manual_collect 惯例,数据源删除后关系保留);`db_name` 空串兜底口径与 manual_collect 一致(无库概念方言存空串)。

- **table_relation**(表间关系):四元组 `datasource_id/db_name/schema_name` + 方向化存储 `one_table/one_column`(唯一侧)与 `many_table/many_column`(重复侧)+ `cardinality`(ONE_TO_ONE/ONE_TO_MANY/SUSPECT_MANY_TO_MANY)+ `status`(CANDIDATE/CONFIRMED/REJECTED)+ `source`(NAME_MATCH/SEMANTIC/MANUAL)+ `confidence`(HIGH/MEDIUM/LOW,可空)+ `overlap_ratio`(值交集率,可空)+ `remark` + 时间戳;唯一键 = 四元组 + 两端表/字段六元组
- **relation_infer_job**(推导任务):四元组 + `anchor_table` + `anchor_columns`(锚点字段 JSON 串,如 `[{"name":"id","aliases":["work_order_id"]}]`;读侧兼容 M1 初期逗号分隔旧格式)+ `use_semantic` + `status`(RUNNING/DONE/FAILED)+ `stage`(NAME_MATCH/SEMANTIC_TABLE/SEMANTIC_COLUMN/VERIFY)+ `total_steps/done_steps/found_count` + `error` + 三个时间戳

## 异步任务与轮询

- 推导统一走异步任务(单线程守护线程池),名字匹配通常 1s 内完成,前端无感;语义匹配分批发 LLM 耗时较长,按 stage 推进(NAME_MATCH → SEMANTIC_TABLE → SEMANTIC_COLUMN → VERIFY)
- `RelationInferDialog` 自成闭环:提交后 1s 轮询 `GET /api/relation-infer-jobs/{id}`,DONE/FAILED 终态停轮询;**关闭对话框即停轮询**(任务在后端继续跑,重开不追溯)
- 语义通道容错:单批/单表 LLM 调用失败记日志并附注 `job.error`,继续其余批次不炸任务(名字匹配结果必须保住)
- **服务重启时残留 RUNNING 任务标 FAILED**(error=服务重启中断;推导可重跑,不做断点续推)

## 降级

未配置大模型时:推导对话框语义匹配开关置灰(仅名字匹配),功能整体仍可用;强行提交 `useSemantic=true` 后端直接拒绝(409)。语义匹配调用计入 `ai_usage_log`(场景「关系推导」)。

## 已知限制

- **布局不持久化**:节点位置每次渲染按当前布局重排(「导出 .drawio」可定格当前布局,交付图以 drawio 文件承载)
- **单轮候选上限 200**:超出截断(防整库同名字段爆量),可换锚点字段再推
- **无全库两两推导**:N 跳 = 人工跳,图上「以此为锚点推导」逐圈扩展
- **图片/Word 嵌图未做**(按讨论稿结论延后);过渡路径:「导出 .drawio」后在 draw.io 中编辑并导 PNG
