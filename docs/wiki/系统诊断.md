# 系统诊断(排错中心)

> 一级页面「系统诊断」(`/diagnostics`,侧边栏入口),让用户自助排错:一页聚合运行环境、AI 配置、数据源连通性实测、最近扫描/导出失败记录、最近错误日志,并可导出 Markdown 诊断报告发给运维/开发。

## 页面与 API

| 入口 | 说明 |
|---|---|
| `GET /api/diagnostics` | 诊断概览(快路径,全本地聚合):环境 + 授权 + AI 配置完整性 + 最近失败记录 + 错误日志摘录 |
| `POST /api/diagnostics/check-datasources` | 全部已存数据源连通性实测(慢路径,页面「数据源连通性」区块内「开始检测」按钮手动触发) |

- 页面:`web/src/views/Diagnostics.vue`;聚合逻辑:`common` 的 `DiagnosticsService`(模型在 `model/Diagnostics.kt`);server 仅薄壳 `DiagnosticsController`。
- `/api/diagnostics` 前缀在授权前置校验中**放行激活检查**(未激活恰是最需要诊断的场景,与 `/api/license` 同待遇);前端路由守卫同样放行 `/diagnostics`。

## 各检查项口径

- **运行环境**:版本(`config.appVersion`)、Java/OS、CPU、堆内存、JVM 运行时长、数据目录、磁盘剩余、H2 库文件(`*.mv.db`)总大小。
- **授权状态**:`DiagnosticsService` 仍聚合 `LicenseService.status()` 字段,但页面不展示该区块(授权激活引导在「系统设置」页),导出的 Markdown 报告也不含。
- **AI 配置**:只报配置完整性(`AiConfigService.findConfig()`),**不实测连通**——实测会记一次 AI 用量,实测入口在「系统设置 → AI 配置」。
- **数据源连通性**:`dataSourceService.get(id)` 取解密配置映射为 `TestConnectionRequest`,复用 `testConnection()`(可经一次性 SSH 隧道);线程池(最多 4)并发,单条 30s 超时兜底,单个失败不影响其他;前端该接口请求超时放宽到 60s。
- **最近扫描失败**:`scan_job` 最近 10 个 FAILED 任务(`ScanRepository.listRecentFailedJobs`),各带前 20 张 FAILED 表(表名 + `scan_table.error`);任务级错误在 `scan_job.error`。
- **最近导出失败**:仅 Word 数据调研报告异步导出任务(`report_export` 表,最近 200 条中内存过滤 FAILED 取前 10;含数据源名/数据库/库范围);扫描 Excel 导出、列表导出等走浏览器直接下载,无失败记录。
- **最近错误日志**:server 侧 `LogStreamAppender` 内存环形缓冲(500 条)中最近 50 条 WARN/ERROR;运行日志已转为普通功能,不再按授权码门控,任何实例(含未激活)都返回摘录。
- **导出诊断报告**:前端把已加载数据组装 Markdown(`utils/download.js` 的 `downloadText`,Blob 下载),文件名 `dq-diagnostic-YYYYMMDD-HHmmss.md`;数据源未实测时报告标注「未检测」。

## 敏感信息边界

- 报告不含任何密码/SSH 秘密:数据源清单走 `DataSourceService.list()`(秘密置 null),解密配置仅在实测内存中使用。
- jdbcUrl、用户名、数据目录路径会出现在报告里(排错必需;本工具仅内网单机部署,可接受)。
