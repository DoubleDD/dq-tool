# 更新日志(Changelog)

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。
> 单一事实来源 = 仓库根 `CHANGELOG.md`(人维护,Keep-a-Changelog 简式);构建期拷入 jar,后端解析后经 API 给前端。
> 流程强制:每个版本都必须有对应段落,构建有硬校验(见下「构建校验」)。

## 文件格式约定

```markdown
# 更新日志

## 1.9.8 (2026-09-06)

### 新增

- **条目一**:说明文字,可含 `行内代码`
- 条目二

### 变更

- 条目三
```

- 段落标题 = `## <展示版版本号> (发布日期)`;**展示版 = VERSION 去掉 `0.` 前缀**(如 `0.1.9.8` → `1.9.8`),与页脚版本号、安装包版本口径一致
- 日期可省略;文件顺序即最新在前(新段落插在最上面)
- 段内正文就是**标准 Markdown**:`### 新增/变更/修复` 分节、`- ` 列表、`**加粗**`、`` `行内代码` ``、有序列表、表格、代码块等按 Markdown 语义渲染。后端只负责切段并原样透传正文(保留段内空行与行首缩进,以兼容嵌套列表),渲染由前端 `marked` 完成

## 功能入口

| 入口 | 页签 | 内容 |
|------|------|------|
| 新版本首次打开自动弹出 | 「本次更新」(`/whats-new`) | 仅当前版本条目;查不到时显示「本次版本暂无更新说明」,底部有「查看历史版本更新记录」链接 |
| 点击页脚版本号 | 「更新记录」(`/changelog`) | 全部历史版本条目(最新在前) |

- 两路由共用 `web/src/views/Changelog.vue`,路由 props 传 `mode: latest / all`;固定页签登记在 `tabs.js` 的 `PAGE_TABS`
- 正文渲染:前端用 `marked`(web 依赖)把段落 Markdown 解析成 HTML,一次性解析后随条目缓存(不每次重渲染都解析全部历史)。CHANGELOG.md 是**构建期打包进 jar 的静态可信内容**(非用户输入/上传,运行期不可改),故直接 `v-html` 输出、不引入 DOMPurify 之类的清洗依赖;Markdown 正文样式必须写在**非 scoped** style 块里(注入元素拿不到 SFC 的 scope id,`[data-v-x]` 选择器会全部失配)
- 首启判定(App.vue `checkWhatsNew`):复用路由守卫的 `fetchLicenseStatus()` 拿 `appVersion`;`dev` 版本或未激活跳过;`localStorage['dq-seen-version']` 与当前版本相同则跳过,不同则**先写回**再请求 `/api/changelog` 确认存在当前版本条目,有才 `router.push('/whats-new')`(先写回防接口失败/中途关页导致重复弹)
- 接口 `GET /api/changelog` 在授权前置校验白名单内(与 `/api/diagnostics` 同理,未激活也能看)

## 链路

```
CHANGELOG.md(仓库根,人维护)
  └─ server/build.gradle.kts  processResources 拷入 jar 根(classpath /CHANGELOG.md)
       └─ common ChangelogService  构造时读 classpath 切成版本条目(ChangelogEntry: version/date/markdown,markdown = 段落原始 Markdown 正文,保留空行与行首缩进);
          资源缺失/为空 → 空条目列表,不抛异常;currentVersion 取 config.appVersion
            └─ GET /api/changelog(ChangelogController 薄壳)→ ChangelogView(currentVersion, entries)
                 └─ 前端 Changelog.vue 交给 marked 渲染正文,条目缓存解析结果
```

## 构建校验(verifyChangelog)

`server/build.gradle.kts` 的 `verifyChangelog` 任务挂在 `processResources` 前置(dev 运行与 release 打包都必经):
校验 `CHANGELOG.md` 存在以 `## <展示版>` 或 `## <原始VERSION>` 开头的段落,缺失即 `GradleException` 并提示填写——硬性保证"每个版本都要加 changelog"。

`scripts/bump-version.sh` 升版本号时,若 `CHANGELOG.md` 缺少新展示版段落,自动在 `# 更新日志` 标题行后插入占位模板段落(版本号+当天日期+一行待填写条目),发版人只需填写内容;发版步骤见 [打包与发布](打包与发布.md)。
