# 桌面版生命周期与数据目录

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。本文覆盖桌面安装版生命周期、headless 行为、数据目录与日志。Tauri 壳细节见 [tauri/AGENTS.md](../../tauri/AGENTS.md)。

- 桌面安装版生命周期(2026-08 启动优化后;2026-09 移除启动画面):HTTP 绑定后**立即开窗**(Chromium 系浏览器 --app,`BrowserOpener`;首选浏览器可在「系统设置 → 浏览器」指定,DB `system_settings.browser_app` 持久化,因开窗早于 H2 就绪,选择同时镜像到 `data/browser-app.txt` 供冷启动读取,内核就绪后再以 DB 为准回填;「自动」按系统优先级 Windows 先 Edge、macOS/Linux 先 Chrome),页面外壳秒出并展示**实时启动阶段**(`/api/health` 未就绪时返回 `stage`,占位页点亮"加载配置/启动服务/初始化数据"步骤);**共享内核(H2 池+建表/迁移/中断恢复)与 Web 装配/开窗并行构建**(`kernel-init` 后台线程,`finishInit(kernelFuture)` 等结果后注入控制器引用),前端轮询到 200 再加载数据。**首次 AWT 初始化推迟到开窗后**由主线程完成(`DqApplication.ensureAwtInitializedOnMainThread`),避免 AWT 落在托盘后台线程;托盘图标**后台安装**(`TrayManager.installEarlyAsync`,主流程不等待,`markTrayReady` 见安装进行中不阻塞)。早期反馈只在显式 `-Djava.awt.headless=false`(打包脚本注入)时启用,普通 java -jar 不触发;托盘右键菜单「打开窗口/退出」,退出=关窗口+结束后端进程;托盘生效时后端以守护进程方式常驻、心跳看门狗停用;托盘不可用(headless/部分 Linux 桌面)时退回心跳看门狗(DesktopSession):前端按心跳间隔上报 `/api/heartbeat`(系统设置 → 页面心跳可调,单位秒/分/时,默认 5 秒,DB `system_settings.heartbeat_interval_seconds` 持久化,保存后前端即时重建定时器),超过 max(`dq.desktop.shutdown-timeout-seconds`(默认 45s,<=0 禁用), 3 个心跳间隔) 未收到心跳自动退出(间隔调大后窗口开着不会被误杀,代价是关窗后退出更慢);只在本进程成功拉起 --app 窗口后才武装,java -jar 服务器部署不受影响;机器休眠/进程被系统挂起不会误判退出(看门狗每轮对比墙钟与单调钟增量识别挂起,唤醒后跳过判定并把心跳基线重置到唤醒时刻,窗口还开着时前端恢复后立即补心跳,窗口真关了仍按超时退出);进行中的扫描随进程退出中断,重开后可断点续扫
- 架构决策(2026-08):**彻底放弃并删除 Kotlin Compose Desktop 与 JCEF shell 两套桌面方案**(Compose 生态不足、基础组件需自绘、工作量大;JCEF 体积约 200MB)。桌面分发只保留两条路:server 安装版浏览器 --app 窗口(jpackage)与 Tauri 2 套壳(`tauri/`)
- 注意:应用默认 headless(`DqApplication.main` 首行设置,与原 Spring Boot 行为一致),本地 `java -jar`/`./gradlew :server:run` 调试窗口与托盘需显式加 `-Djava.awt.headless=false`(打包脚本已注入);进程退出统一走 `AppShutdown`(停 Javalin → 关 Hikari → System.exit(0))
- H2 文件损坏自愈(`common/env/H2StoreRepair`,2026-09 随启动预检引入):客户跨版本升级/异常关机后 `*.mv.db` 可能 MVStore 损坏(启动报 `File corrupted in chunk ...` 直接退出)。`kernel-init` 线程在 `new ServiceEnv` 打开连接池之前先做健康预检(此刻单实例锁已保证独占数据目录):逐库(主库 `dqconfig` + AI 用量库 `dqaiusage`)以正式启动同款 `AUTO_SERVER=TRUE` URL 探测打开一次(可自动接管上次强杀留下的残留 `.lock.db`,不带 AUTO_SERVER 的 URL 遇残留锁会报 90020 卡死启动),异常链确认为 MVStore 损坏才修复——损坏文件重命名为 `<库名>-corrupted-<时间戳>.mv.db` **永久备份不删除**,再用 H2 自带 `Recover` 导出 `<备份名>.h2.sql` 并 `RunScript` 重建(continueOnError 尽量多救数据);导出/重建失败则以空库启动(Flyway 建表,数据走导入功能恢复),保证程序一定起得来。全过程落 `startup.log`。注意 H2 工具类内部有裸 assert,损坏文件可能抛 `AssertionError`,修复代码按 `Throwable` 兜底;非损坏类打开失败(如文件被占用)不碰任何文件、原样上抛
- 数据目录与日志:开发/`java -jar` 方式数据目录为 `./data`;安装版为 `~/.dq-tool/data`(带点隐藏目录,打包脚本注入 `-Ddq.data-dir`)。**JVM 全局临时目录在 main 早期重定向到数据目录下 `tmp/`**(`JvmTmpDir.redirect`,加载配置后、logback 初始化与内核线程前调用):系统临时目录(%TEMP%/tmp)会被存储感知/安全软件清扫,POI SXSSF 正在写的临时文件被删导致导出 `NoSuchFileException`(现场报错 HTTP 409 + `...\Temp\poifiles\poi-sxssf-sheet*.xml`);重定向后 SXSSF 落 `tmp/poifiles`(启动时清扫上次进程崩溃残留),Jetty 上传等其余临时文件也一并收进数据目录——须早于任何临时文件使用方初始化(JDK 首次使用 `java.io.tmpdir` 即固化,之后改属性无效)。运行日志在 **数据目录同级的 `logs/` 目录**(如安装版 `~/.dq-tool/logs/`,规则单点 `StartupLog.logDirFor`,`-Ddq.log-dir` 可显式覆盖):`dq-tool.log` 追加写、按天滚动为 `dq-tool.yyyy-MM-dd.log`,单个文件最大 100MB、一天内超限按 `%i` 序号拆分,保留 30 天、总量上限 2GB(`SizeAndTimeBasedRollingPolicy`,配置见 `server/src/main/resources/logback.xml`,路径变量 `${dq.log-dir:-./logs}` 由 main 在任何日志输出前设置);启动早期日志(logback 初始化前 + 未捕获异常)在同目录 `startup.log`(`config/StartupLog`,仅追加)
