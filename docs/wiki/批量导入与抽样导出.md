# 表格批量导入与抽样导出

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。

上传一张「每行一张表」的 xlsx(样例 `docs/1导入数据.xlsx`),一次上传 = 一个**抽样导出大任务**,后台依次做两件事:① 提取去重数据源加入系统(连不上的建档并标记错误,等人工处理);② 每行表抽 50 行数据,按「数据源 × 所属水利对象类别」产出 xlsx,按类别目录归档后整包 zip。前端「抽样导出」页(`/sample-exports`)管理任务,列表 1s 轮询。

## 输入 Excel 格式

单 sheet,表头 12 列(按表头名去空白定位,顺序不限):`所属水利对象类别名称 | 系统编号 | 实际系统或模式描述 | 数据库类型 | 地址 | 端口 | 用户名 | 口令 | 数据库名称 | 模式名称 | 表英文名称 | 表中文名称`。

- 解析器 `service/SampleTableExcelParser.kt`(object 纯函数):XSSFWorkbook + DataFormatter 取显示字符串(端口/数字口令是数值单元格也能读);全空行跳过;必需列=数据库类型/地址/数据库名称/表英文名称,缺失的行收集为 SkippedRow(进任务 ds_report 记 `ROW_SKIPPED`),有效行为 0 则 400
- 端口空按方言默认(3306/5432/1433/1521/5236/54321/2881/5866,`JdbcUrlRewriter.defaultPort` 公有化后唯一来源);地址 trim;用户名/口令空归一为 null;数据库类型支持 mysql/kingbase/sqlserver/oracle/postgresql/dm/highgo/oceanbase(大小写不敏感)
- **口令只活在内存**(解析行直接传后台线程),明细表 `sample_export_item` 不落口令列

## 阶段一:数据源去重导入

- **身份 key(dsKey)**:`dbType|host小写|port|username|database`,**不含口令、不含模式名**(同服务同库不同口令视为同一数据源;模式是明细级信息)。已存数据源侧用 `keyOfExisting`:JdbcUrlRewriter 解析 host/port + 按方言从 jdbcUrl 反解库名(mysql/pg/kingbase/highgo/oceanbase 取路径段,sqlserver 取 `databaseName=`(不区分大小写),oracle 取 `@//` 后服务名,dm 恒空串),解析不出不参与匹配
- 处理动作(ds_report 逐条记录,前端明细可见;每行带 `datasourceId` 回绑——除解析失败的 `ROW_SKIPPED` 行为 null——供前端点名称直接弹数据源编辑框):
  - 不存在 → 并发实测(4 线程 + 单条 20s 超时,写法照 DiagnosticsService)后**成败都建档**(名称=`实际系统或模式描述(数据库名称)`,重名加 ` (2)` 后缀,分组「表格批量导入」):通 → `ADDED` + conn 标记 OK;不通 → `ADDED_ERROR` + conn 标记 ERROR(错误消息落库,数据源页卡片红框「连接失败」+ tooltip 显示,等人工修复)
  - 已存在且 conn 状态非 ERROR → `SKIPPED`(不重复测连,直接复用)
  - 已存在且 conn 状态 ERROR → 用 Excel 连接信息实测:通 → 只更新连接信息(jdbcUrl/用户名/密码;**分组/阈值/库过滤/SSH 隧道等既有配置一律保留**,批量导入不改历史数据源的设置)+ conn 状态置 OK 但**旧错误消息保留作历史** → `FIXED`;不通 → 刷新错误消息 → `STILL_ERROR`
- 测连只读无副作用放线程池;建档/修复落库全部在主线程串行,避免超时后后台线程与主线程重复建档的竞态
- **SQL Server 默认高级参数**(`SampleExportService.withMssqlDefaults`):批量导入的 Excel 拼出的 jdbcUrl 不带高级连接参数,而 mssql-jdbc 高版本默认 encrypt=true 且严格校验证书,老版本 SQL Server 直接连不上;故实测与建档/修复更新 jdbcUrl 前,对 `jdbc:sqlserver:` URL 自动补上与数据源页「高级」页签一致的默认组合 `encrypt=true;trustServerCertificate=true;sslProtocol=TLSv1.1`,URL 里已有(任意大小写)的参数不覆盖;其他类型 URL 原样透传
- **连接错误标记**:`data_source` 表 V24 新增 `conn_status`(NULL/OK/ERROR)/`conn_error`/`conn_checked_at` 三列;只由本功能写入,数据源 CRUD 其他路径不清不动

## 阶段二:按组导出表数据

- **一个 Excel = 一个(数据源 × 类别)**(类别空归一「未分类」):需求字面是「一个数据源一个 Excel」,但实测样例里 27 个数据源有 15 个跨类别(最多跨 25 个),单文件无法同时满足「按类别目录归档」,故按 数据源×类别 出文件——同一数据源的数据不会与其他数据源混在同一文件,同类别的文件进同一目录
- 产物落盘 `数据目录/sample-exports/task-<id>/<类别>/<数据源名>.xlsx`(文件名 `\/:*?"<>|` → `_`;同名冲突追加 `-<dsId>`)
- 每个 xlsx 第一个 sheet 固定「**预览目录**」,表头:`序号 系统来源名称 实际系统或模式描述 数据库名称 模式名称 表中文名称 表英文名称 预览sheet名 样本行数 备注`;**系统来源名称列留空**;数据行在组内表全部处理完后回填(失败的表 备注=错误消息、预览sheet名 留空、不建数据 sheet)
- 数据 sheet 命名规范:`模式名称.表英文名称`(模式为空用库名兜底;同名只出现一次,再经 `util/ExcelCells.kt` 的 sheetName 清洗:非法字符替换、31 字符截断、重名 `_2/_3`)
- 抽样:`dialect.sampleRowsSql(schema ?: database, table, 空列, 50)`(8 方言各有 LIMIT/TOP/ROWNUM 实现),表头取 ResultSetMetaData 列名;单元格 null→空串、Number→数值、其他 toString 截断 1000(与数据预览同口径);`stmt.queryTimeout` 取系统设置的单条 SQL 超时;数据源阶段一即连不上的,其下表不进查询直接 FAILED(「数据源无法连接: …」)
- 内存 XSSFWorkbook 写(每表 ≤50 行,且「预览目录」要回填,不用 SXSSF 流式)

## 阶段三:打包与产物

- `task-<id>` 目录打成 `sample-exports/task-<id>.zip`(ZipOutputStream 显式 UTF-8,zip 内顶层即类别目录);无任何 xlsx 产出则 zip_path 留 null(前端隐藏下载)
- 下载名 `<原Excel名去扩展名>-抽样导出-<id>.zip`;「打开目录」调 `SystemOpen.openDir`(mac `open` / win `explorer` / linux `xdg-open`,直接打开任务产物目录)

## 任务模型与 API

- 表(V24 迁移):`sample_export`(任务:状态机 PENDING→RUNNING→DONE/FAILED、stage、total/done_items、ds 五计数、ds_report CLOB JSON、zip_path/size、三时间戳)+ `sample_export_item`(明细:Excel 行全字段 + ds_key + datasource_id 回绑 + sheet_name/status/row_count/error/excel_file;task_id 外键级联);服务重启未完成任务与明细统一置 FAILED(`recoverUnfinished`,initDatabase 调用)
- 执行:`SampleExportService` 单线程守护队列(照 WordReportExportService);**进度口径**:处理前 `updateStage` 亮当前表名,完成后 `updateProgress(done, total)`,`finish()` 兜底 `done_items=total_items`
- **暂停/恢复**:运行中任务可暂停为 PAUSED(仅 RUNNING→PAUSED 生效,排队中不可暂停);工作线程在任务级检查点挂起等待——数据源导入逐源、导出逐表、打包前各查一次状态,粒度是「下一个检查点」(单个数据源实测最长 20s、单表查询中途不打断);恢复由 `pauseLock` notify 唤醒;暂停中任务被取消删除时工作线程抛 `TaskCancelledException` 静默退出
- **批量删除**(`POST /api/sample-exports-delete`,body `{"ids":[...]}` → `{deleted, skipped}`):完成/失败任务删记录(task_id 外键级联明细)与产物(task-<id> 目录 + zip);暂停中任务先置 FAILED 唤醒工作线程再删,即「取消并删除」;排队中/运行中跳过进 skipped;产物删除失败只告警不阻塞记录删除
- API(`controller/SampleExportController.java`):
  - `POST /api/sample-exports`(multipart `file`,限 .xlsx)→ `{taskId}`
  - `GET /api/sample-exports` → 任务列表(含 ds 五计数与 zip 信息)
  - `GET /api/sample-exports/{id}` → 详情(任务 + dsReport 数组 + items 全列,items 附 datasourceName)
  - `GET /api/sample-exports/{id}/download` → zip 流
  - `GET /api/sample-export-template` → 导入模版 xlsx(表头 + 一行示例,`SampleTableExcelParser.writeTemplate`;**刻意避开 `/api/sample-exports/` 前缀**——实测同前缀静态段会被 `{id}` 路径参数路由吃掉报 400;批量删除同理注册为 `/api/sample-exports-delete`)
  - `POST /api/sample-exports/{id}/open-dir` → 系统文件管理器打开产物目录
  - `POST /api/sample-exports/{id}/pause` / `POST /api/sample-exports/{id}/resume` → 暂停/恢复

## 已知边界

- SQL Server 若遇 `"encrypt" property is set to "true"...` 证书错误、Oracle 遇 `ORA-12514`(Excel 的「数据库名称」填的是 schema 而非服务名)等,属**数据源本身需要人工修正**的场景:功能按设计标记 ERROR 并给出原始驱动错误消息,用户在数据源页修复(如 sqlserver 补 `;trustServerCertificate=true`)后,下次导入走 `FIXED` 路径自动清除标记
- 同 dsKey 多行口令不一致时按首行口令建档(dedup 保序);样例 Excel 无此情况
- 达梦/金仓/OceanBase/Oracle/瀚高的导出查询无自动化覆盖(同项目既有测试矩阵口径),只经真实环境验证
