# 表格批量导入与抽样导出

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。

上传一张「每行一张表」的 xlsx(样例 `docs/1导入数据.xlsx`),一次上传 = 一个**抽样导出任务**,后台按**显式两步流程**执行:

1. **第一步·数据源检测**:提取去重数据源加入系统(连不上的建档并标记错误,等人工处理),检测完成任务停在「待导出」(DETECTED)——**不再自动往下走**;
2. 用户看检测结果决策:数据源有问题可**就地编辑数据源**(当前页面弹编辑框,不跳数据源页)或**重新导入表格**(新 Excel 全量替换明细并重跑检测)修复;
3. **第二步·导出数据**:用户点「继续导出」后,每行表按 Excel「数据量」列抽样(留空或未提供该列默认 50 条),按「数据源 × 所属水利对象类别」产出 xlsx,按类别目录归档后整包 zip。

前端「抽样导出」页(`/sample-exports`)管理任务,列表 1s 轮询(仅 PENDING/RUNNING 轮询,DETECTED 是等待用户决策的静止状态)。设计要点:**两步之间不保留内存中的 Excel 解析行(含口令)**,第二步按 ds_key 从库中重新解析数据源再导出,用户在两步之间修过的连接信息都能生效;口令全程只活在检测线程执行期内。

## 输入 Excel 格式

单 sheet,表头 12 列(按表头名去空白定位,顺序不限):`所属水利对象类别名称 | 系统编号 | 实际系统或模式描述 | 数据库类型 | 地址 | 端口 | 用户名 | 口令 | 数据库名称 | 模式名称 | 表英文名称 | 表中文名称`,另有一列**可选**的 `数据量`(导出抽样条数,旧表格无此列)。

- **「数据量」列(可选,见 V26 `sample_limit`)**:控制该表导出多少条数据;留空、缺列、非数字或非正数一律按默认 50 条(旧表格没有该列即此口径)

- 解析器 `service/SampleTableExcelParser.kt`(object 纯函数):XSSFWorkbook + DataFormatter 取显示字符串(端口/数字口令是数值单元格也能读);全空行跳过;必需列=数据库类型/地址/数据库名称/表英文名称,缺失的行收集为 SkippedRow(进任务 ds_report 记 `ROW_SKIPPED`),有效行为 0 则 400
- 端口空按方言默认(3306/5432/1433/1521/5236/54321/2881/5866,`JdbcUrlRewriter.defaultPort` 公有化后唯一来源);地址 trim;用户名/口令空归一为 null;数据库类型支持 mysql/kingbase/sqlserver/oracle/postgresql/dm/highgo/oceanbase(大小写不敏感)
- **口令只活在内存**(解析行直接传后台线程),明细表 `sample_export_item` 不落口令列

## 阶段一:数据源检测(去重导入)

检测是任务的第一步,**跑完即停**(任务置 DETECTED 等用户决策),不与导出连着跑。

- **身份 key(dsKey)**:`dbType|host小写|port|username|database`,**不含口令、不含模式名**(同服务同库不同口令视为同一数据源;模式是明细级信息)。已存数据源侧用 `keyOfExisting`:JdbcUrlRewriter 解析 host/port + 按方言从 jdbcUrl 反解库名(mysql/pg/kingbase/highgo/oceanbase 取路径段,sqlserver 取 `databaseName=`(不区分大小写),oracle 取 `@//` 后服务名,dm 恒空串),解析不出不参与匹配
- 处理动作(ds_report 逐条记录,前端明细可见;每行带 `datasourceId` 回绑——除解析失败的 `ROW_SKIPPED` 行为 null——供前端点名称直接弹数据源编辑框):
  - 不存在 → 并发实测(4 线程 + 单条 20s 超时,写法照 DiagnosticsService)后**成败都建档**(名称=`实际系统或模式描述(数据库名称)`,重名加 ` (2)` 后缀,分组「表格批量导入」):通 → `ADDED` + conn 标记 OK;不通 → `ADDED_ERROR` + conn 标记 ERROR(错误消息落库,数据源页卡片红框「连接失败」+ tooltip 显示,等人工修复)
  - 已存在且 conn 状态非 ERROR → 直接复用不重复测连;**名称以本次导入的表格为准**——与已存名不同则改名(只动 name 列,`DataSourceRepository.updateName`,连接状态标记不清;被别的数据源占用时自动加后缀)→ `RENAMED`,相同 → `SKIPPED`(RENAMED 计入列表「跳过」数)
  - 已存在且 conn 状态 ERROR → 用 Excel 连接信息实测:通 → 更新连接信息(jdbcUrl/用户名/密码)并按表格改名;**分组/阈值/库过滤/SSH 隧道等既有配置一律保留**,批量导入不改历史数据源的设置;conn 状态置 OK 但**旧错误消息保留作历史** → `FIXED`;不通 → 刷新错误消息 → `STILL_ERROR`
- 测连只读无副作用放线程池;建档/修复落库全部在主线程串行,避免超时后后台线程与主线程重复建档的竞态
- **SQL Server 默认高级参数**(`SampleExportService.withMssqlDefaults`):批量导入的 Excel 拼出的 jdbcUrl 不带高级连接参数,而 mssql-jdbc 高版本默认 encrypt=true 且严格校验证书,老版本 SQL Server 直接连不上;故实测与建档/修复更新 jdbcUrl 前,对 `jdbc:sqlserver:` URL 自动补上与数据源页「高级」页签一致的默认组合 `encrypt=true;trustServerCertificate=true;sslProtocol=TLSv1.1`,URL 里已有(任意大小写)的参数不覆盖;其他类型 URL 原样透传
- **连接错误标记**:`data_source` 表 V24 新增 `conn_status`(NULL/OK/ERROR)/`conn_error`/`conn_checked_at` 三列;由本功能与数据源编辑写入——**编辑数据源保存连接信息后三列清零回到「未检测」**(`DataSourceService.update` → `clearConnStatus`,旧错误随旧连接信息一并过时),导出前复测据此拿到最新状态;数据源 CRUD 其他路径(库过滤/分组等)不清不动

## 阶段二:按组导出表数据(用户点「继续导出」后)

- **导出前重新解析数据源**(`resolveOutcomesForExport`):不沿用检测阶段的内存结果(解析行含口令,检测线程结束即丢弃),而是按 ds_key 从 `data_source` 重新匹配——用户在两步之间**就地编辑数据源**(连接信息已更新、conn_status 已清零)或**重新导入 Excel**修过的连接,这里都能拿到最新状态;`conn_status=ERROR` 的用**已存连接信息**并发复测(4 线程 + 单条 20s 超时,与检测同一 `testConnectionsConcurrently`),连通回写 OK(旧错误保留作历史)放行,仍不通维持 ERROR、其下表记「数据源无法连接: …」FAILED;匹配不到已存数据源(被删/解析不出)的明细直接 FAILED。明细的 `datasource_id` 也在本阶段重新回绑
- **一个 Excel = 一个(数据源 × 类别)**(类别空归一「未分类」):需求字面是「一个数据源一个 Excel」,但实测样例里 27 个数据源有 15 个跨类别(最多跨 25 个),单文件无法同时满足「按类别目录归档」,故按 数据源×类别 出文件——同一数据源的数据不会与其他数据源混在同一文件,同类别的文件进同一目录
- 产物落盘 `数据目录/sample-exports/task-<id>/<类别>/<数据源名>.xlsx`(文件名 `\/:*?"<>|` → `_`;同名冲突追加 `-<dsId>`)
- 每个 xlsx 第一个 sheet 固定「**预览目录**」,表头:`序号 系统来源名称 实际系统或模式描述 数据库名称 模式名称 表中文名称 表英文名称 预览sheet名 样本行数 备注`;**系统来源名称列留空**;数据行在组内表全部处理完后回填(失败的表 备注=错误消息、预览sheet名 留空、不建数据 sheet)
- 数据 sheet 命名规范:`模式名称.表英文名称`(模式为空用库名兜底;同名只出现一次,再经 `util/ExcelCells.kt` 的 sheetName 清洗:非法字符替换、31 字符截断、重名 `_2/_3`)
- 抽样:`dialect.sampleRowsSql(schema ?: database, table, 空列, limit)`(8 方言各有 LIMIT/TOP/ROWNUM 实现),limit 取明细 `sample_limit`(Excel「数据量」列),未填按 50;表头取 ResultSetMetaData 列名;单元格 null→空串、Number→数值、其他 toString 截断 1000(与数据预览同口径);`stmt.queryTimeout` 取系统设置的单条 SQL 超时;数据源阶段一即连不上的,其下表不进查询直接 FAILED(「数据源无法连接: …」)
- 内存 XSSFWorkbook 写(每表 ≤50 行,且「预览目录」要回填,不用 SXSSF 流式)

## 阶段三:打包与产物

- `task-<id>` 目录打成 `sample-exports/task-<id>.zip`(ZipOutputStream 显式 UTF-8,zip 内顶层即类别目录);无任何 xlsx 产出则 zip_path 留 null(前端隐藏下载)
- 下载名 `<原Excel名去扩展名>-抽样导出-<id>.zip`;「打开目录」调 `SystemOpen.openDir`(mac `open` / win `explorer` / linux `xdg-open`,直接打开任务产物目录)

## 任务模型与 API

- 表(V24 迁移,V26 明细表加 `sample_limit` 抽样条数列):`sample_export`(任务:状态机 PENDING→RUNNING(检测)→**DETECTED(检测完成,等用户决策)**→RUNNING(导出)→DONE/FAILED、stage、total/done_items、ds 五计数、ds_report CLOB JSON、zip_path/size、三时间戳)+ `sample_export_item`(明细:Excel 行全字段 + ds_key + datasource_id 回绑 + sheet_name/status/row_count/sample_limit/error/excel_file;task_id 外键级联);DETECTED 是等待用户决策的静止状态,服务重启不清理(只 PENDING/RUNNING/PAUSED 置 FAILED,`recoverUnfinished`,initDatabase 调用)
- 执行:`SampleExportService` **固定 4 线程池**(刻意不用单线程队列:任务可在检查点暂停长时挂起,单线程会让暂停中的任务堵住后面所有任务;检测与导出都走该池,多个任务可并发跑);并发任务间数据源「查重→建档/修复」经 JVM 锁 `dsWriteLock` 互斥——锁内按最新库重判(另一任务可能刚建过同一 dsKey),名称去重也在锁内按最新库计算,不会重复建档;**进度口径**:处理前 `updateStage` 亮当前表名,完成后 `updateProgress(done, total)`,`finish()` 兜底 `done_items=total_items`
- **检测明细实时可见**(`writeTestingReport` + `testConnectionsConcurrently`):**在并发测连之前**即把全部唯一数据源以 `QUEUING`(排队中)连同基础信息(名称/类型/地址/端口/库名)落 ds_report(测连期间明细不留空白),前端明细立刻列出全部待测数据源。生命周期三态按真实推进逐行翻转:**排队中**(还在测连池队列里等)→ **校验中**(`onStart` 回调,任务真正进线程开始执行才触发)→ 最终结果(`onEach` 按完成先后触发,ExecutorCompletionService:谁先测完谁先出结果,排在前面的慢源/超时源不堵后面的快源;单条超 20s 记「连接超时」并取消);免测源(已存在且非 ERROR)最后统一翻「已跳过」。前端 1s 轮询即可看到状态实时推进。首次检测(`importDatasources`)与重新导入(`reimport` 同步写)共用
- **重新导入**(`POST /api/sample-exports/{id}/reimport`,multipart `file`):仅 DETECTED/FAILED 任务可重新导入;新 Excel 解析后**全量替换**任务明细(`replaceItems`:删旧行、文件名/总数更新、统计/报告/产物路径/错误清零,单事务)并**在接口内同步落「校验中」报告**(不等线程池调度,明细抽屉立刻可见新数据源列表),随后重跑第一步检测——「重新导入表格更新数据源」的修复路径,靠检测的 FIXED/STILL_ERROR 分支用新连接信息更新既有数据源;任务检测完成后再次回到 DETECTED
- **继续导出**(`POST /api/sample-exports/{id}/export`):仅 DETECTED 任务可发起(DETECTED→RUNNING 竞争更新,`markExporting` 返回 0 即状态已被改变),转后台跑 `runExport`(重新解析数据源 → 按组导出 → 打包)
- **暂停/恢复**:运行中任务可暂停为 PAUSED(仅 RUNNING→PAUSED 生效,排队中不可暂停);工作线程在任务级检查点挂起等待——数据源导入逐源、导出逐表、打包前各查一次状态,粒度是「下一个检查点」(单个数据源实测最长 20s、单表查询中途不打断);恢复由 `pauseLock` notify 唤醒;暂停中任务被取消删除时工作线程抛 `TaskCancelledException` 静默退出
- **批量删除**(`POST /api/sample-exports-delete`,body `{"ids":[...]}` → `{deleted, skipped}`):完成/待导出/失败任务删记录(task_id 外键级联明细)与产物(task-<id> 目录 + zip);暂停中任务先置 FAILED 唤醒工作线程再删,即「取消并删除」;排队中/运行中跳过进 skipped;产物删除失败只告警不阻塞记录删除
- API(`controller/SampleExportController.java`):
  - `POST /api/sample-exports`(multipart `file`,限 .xlsx)→ `{taskId}`(创建任务并启动第一步检测)
  - `POST /api/sample-exports/{id}/export` → 用户决策继续导出(第二步)
  - `POST /api/sample-exports/{id}/reimport`(multipart `file`)→ 重新导入并重跑检测
  - `GET /api/sample-exports` → 任务列表(含 ds 五计数与 zip 信息)
  - `GET /api/sample-exports/{id}` → 详情(任务 + dsReport 数组 + items 全列,items 附 datasourceName)
  - `GET /api/sample-exports/{id}/download` → zip 流
  - `GET /api/sample-export-template` → 导入模版 xlsx(表头 + 一行示例,`SampleTableExcelParser.writeTemplate`;**刻意避开 `/api/sample-exports/` 前缀**——实测同前缀静态段会被 `{id}` 路径参数路由吃掉报 400;批量删除同理注册为 `/api/sample-exports-delete`)
  - `POST /api/sample-exports/{id}/open-dir` → 系统文件管理器打开产物目录
  - `POST /api/sample-exports/{id}/pause` / `POST /api/sample-exports/{id}/resume` → 暂停/恢复

## 已知边界

- SQL Server 若遇 `"encrypt" property is set to "true"...` 证书错误、Oracle 遇 `ORA-12514`(Excel 的「数据库名称」填的是 schema 而非服务名)等,属**数据源本身需要人工修正**的场景:功能按设计标记 ERROR 并给出原始驱动错误消息;用户在任务明细里**就地编辑数据源**(或数据源页修复,如 sqlserver 补 `;trustServerCertificate=true`)后连接状态标记自动清零,「继续导出」前会按已存连接信息复测,通过即放行;也可**重新导入表格**走检测的 FIXED 路径更新数据源
- 同 dsKey 多行口令不一致时按首行口令建档(dedup 保序);样例 Excel 无此情况
- 达梦/金仓/OceanBase/Oracle/瀚高的导出查询无自动化覆盖(同项目既有测试矩阵口径),只经真实环境验证
