# 数据源

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。本文覆盖数据源存储加密、SSH 隧道、库过滤、分组、导入导出。

- 数据源连接信息存本地 H2 文件库,密码 AES-GCM 加密
- 业务库连接池(`DataSourceService.pools`,HikariCP):key 为 `数据源id|库名` —— 多库方言(SQL Server/Kingbase)按解析后的目标库**按库分池**,同一物理连接固定一个库,`getConnection(datasourceId, database)` 借出时已切好 catalog(调用方不再自行 `useDatabase`);如此规避 mssql-jdbc 的 `DatabaseMetaData` 缓存语句句柄在 `USE` 跨库后失效不可恢复的坑(错误 586/8179「prepared statement handle is not valid in this context」,驱动默认语句池关闭时不会自动重试);Kingbase 走 PG 协议无法切库,分池 URL 由 `DbDialect.jdbcUrlForDatabase` 改写路径段指向目标库;非多库方言 database 参数忽略,单池。`evictPool` 按 `id|` 前缀回收该数据源全部分池并关闭 SSH 隧道
- Kingbase 多库:`supportsMultiDatabase()=true`,先选库再选 schema(与 SQL Server 同一套跨库浏览/扫描链路);`listDatabases` 查 `pg_database`(排除模板库与禁止连接的库);JDBC URL 未指定库时驱动按用户名当库名导致连接失败,`connectionUrlCandidates` 按序回落维护库候选(原样 → kingbase → test → template1,首个连通者胜),测试连接/库过滤预览/模式探测/默认池建池统一走该回落;库过滤白名单作用层级随之变为数据库级,存量 Kingbase 数据源的 schema 级旧白名单由 V23 迁移清空(旧值在新口径下匹配不到任何数据库)
- SQL Server 版本探测:`SqlServerDialect.detectDbMode` 查 `SERVERPROPERTY('ProductVersion')` 并按主版本号映射营销版本(如 "2014 (12.0.5000.0)"),复用金仓 detectDbMode 同一通道 —— 仅连通性实测时做(排错中心显示「SQL Server 2014 (...)」、诊断报告标「版本」;**保存/新增不再探测落库**,`db_mode` 列仅兼容存量数据);方言行为的版本分支(分页语法等)仍以 `sqlServerMajor(conn)` 实时探测为准,不读该缓存值
- 数据源分组:`data_source.group_name` 自由文本列(空=未分组),不设独立分组表,分组列表由前端从现有数据源聚合去重;编辑对话框「常规」页签可输入新分组或选已有分组(el-select allow-create),数据源页按分组渲染可折叠区块(命名分组按名称排序、未分组排最后、组内保持收藏置顶,全库无分组时退化为平铺网格),可按分组筛选/搜索;卡片可拖拽到其他分组区块(分组头或卡片网格均可放置,拖到「未分组」即移出分组)直接改分组,走轻量接口 `PUT /api/datasources/{id}/group`(`{"groupName": "xxx"}`,null/空白=未分组;只动 group_name 一列,不走全量 PUT 的连库探测);侧边栏数据源菜单同样按分组成组(命名分组为可折叠子菜单、下钻时自动展开所在分组,未分组平铺在最后);分组随导出/导入 JSON 一并迁移(Navicat/DataGrip 导入无分组概念,落为未分组)
- 数据源 SSH 隧道:可配置经跳板机连接目标库(password/publickey 认证,私钥内容入库非文件路径;三个 SSH 秘密字段同样 AES-GCM 加密、编辑留空不改),内核 `SshTunnelService`(SSHJ 本地端口转发)+ `JdbcUrlRewriter`(JDBC URL host:port 解析/改写为 127.0.0.1:转发端口);连接池用长驻隧道(evictPool 一并关闭),测试连接的版本/模式探测用一次性隧道
- 数据源库过滤:数据源级库白名单(`data_source.schema_filter` 逗号分隔,空=不过滤),编辑对话框「库过滤」页签(DataGrip Schemas 页风格)拉取目标库库名勾选 —— 编辑态且连接信息未改(前端快照对比,改过连接字段即失效已拉列表)直接调已存数据源的 `databases`/`schemas` 接口(带 `all=true` 旁路白名单拿全量,切到该页签自动加载;这两个接口为本地 H2 缓存优先——`meta_database` 表,缓存存全量、白名单在读取路径过滤,断网时有缓存即可浏览,`refresh=true` 强制回源覆盖,详见 前端页面与按钮逻辑 库列表页);新增态或编辑态改过连接信息时用 `POST /api/datasources/preview-databases` 按表单连接参数实时连接(请求带 id 时密码/SSH 秘密留空回落已存值;方言 `listDatabases` 为空时回落 `listSchemas`,因为只有 SQL Server/Kingbase 实现了多库列表);白名单作用层级按方言能力区分 —— 多库方言(`DbDialect.supportsMultiDatabase()`,SQL Server/Kingbase)只过滤 `GET /api/datasources/{dsId}/databases`,单库方言(MySQL 等的 schema 即用户眼中的库)过滤 `listSchemas` 与 schema-stats 概览(写入与读取路径都过滤,旧缓存无需重建;MetadataService.applySchemaFilter);库列表页也有「库过滤」弹窗直接改白名单(`PUT /api/datasources/{id}/schema-filter` 单独更新该列,DataSourceService.updateSchemaFilter);系统库不参与业务扫描,各方言在 `DbDialect.systemSchemas()` 给出小写系统库名集合(多库方言为数据库级:SQL Server 的 master/model/msdb/tempdb + SSRS 的 ReportServer 两个组件库、Kingbase 的 kingbase/test/security/template0/1;单库方言为 schema 级:MySQL 四件套、Oracle/DM 内置账号 schema 等),经 `GET /api/db-types/{dbType}/system-schemas` 静态下发(不连业务库),库过滤页签与弹窗拉列表时并行拉取——未配置白名单时系统库默认不勾选并打「系统」灰标(比对大小写不敏感),已配置白名单时按已存配置回填;白名单随导出/导入 JSON 一并迁移
- 数据源导入/导出:数据源页可勾选导出为 JSON(密码与 SSH 秘密字段用内置固定口令 TransferCrypto 重加密,跨实例可导入,仅防随手打开),导入支持本工具 JSON 与 Navicat .ncx(NavicatCrypto 解 Ver 1.x AES-128-CBC 密码;SSH 隧道配置随数据源一并导入,SSH_PrivateKey 只是用户机器上的文件路径读不到内容,非空时提示导入后手动粘贴私钥),重名自动加「 (2)」后缀不覆盖;导入对话框分「文件导入/粘贴导入」两模式,粘贴模式支持 DataGrip「复制数据源到剪贴板」的 XML(带 `#DataSourceSettings#`/`#BEGIN#` 注释行包裹,密码在 IDE 主密码保险箱拿不到,导入后提示逐个编辑补密码)与本工具 JSON 文本,服务端按内容自动识别;逻辑在内核 `DataSourceTransferService`,接口 `GET /api/datasources/export?ids=`、`POST /api/datasources/import`(multipart,文件字段 `file` 或文本字段 `text`);导入的无密码数据源(DataGrip 导入必然无密码、Navicat .ncx 未保存密码、JSON `passwordEnc` 为空时导入成功并带 warning)在数据源卡片上以「未设密码」标出 —— 列表接口从 `password_enc` 判空返回 `hasPassword`(新建密码必填、编辑留空沿用旧值,故无歧义状态,无需持久化列);JSON 导入解析经 `TransferJson` 支持 GBK 转存文件兜底与未知字段忽略(口径见 扫描与Excel导出.md);元数据缓存(结构缓存 + 表说明/标记/ER 关系/数据目录等标注数据)可导出为 JSON 交给连不上业务库的人导入离线使用,行袋格式与替换/合并语义见 [元数据导入导出](元数据导入导出.md)
- 连接状态标记与「网络不可达」分类:`data_source` 四列 —— `conn_status`(NULL/OK/ERROR)、`conn_error`、`conn_kind`、`conn_checked_at`(V24 建前三列,V39 补 `conn_kind`)。有两个写入方:① 表格批量导入的检测与导出前复测(见 批量导入与抽样导出.md);② **元数据浏览/刷新回源**(库/schema/表/字段/索引/库概览)遇连接失败时写 ERROR;③ **ER 关系推导**回源取整库字段清单/取验证连接失败时(见 ER关系推导.md,降级读缓存并用缓存推导)。分类由内核 `util/ConnectionFailureClassifier` 给出:`UNREACHABLE` 网络不可达 / `AUTH` 认证失败 / `OTHER` 其他,判定不依赖具体驱动 —— 沿 cause 链(含 `SQLException.nextException` 链)找 `java.net.*` 异常、叠加 SQLState `08`(connection)/`28`(authorization)与常见英文错误文案(如 `Communications link failure`、`Connection is not available`),因此 8 种数据库通用。回源成功时此前 ERROR 会自愈为 OK(旧 `conn_error` 原样保留作历史,与抽样导出口径一致);**编辑数据源保存连接信息后四列清零**回到「未检测」。除展示外该标记还是 **ER 关系推导的 5 分钟新鲜窗口开关**:窗口内推导不重试连接、直接用本地结构缓存推导(见 ER关系推导.md),超窗或标记被清零后立即重新实测。前端数据源卡片据此显示「网络不可达 / 认证失败 / 连接失败」红框提示(见 前端页面与按钮逻辑)
- 数据源不可达时降级读本地 H2 缓存:元数据浏览链路(库/schema/表/字段/索引/库概览/单表 DDL/schema 字段总数)本就是**缓存优先**(命中本地缓存直接读,不碰业务库);未命中缓存或 `refresh=true` 强制回源时,若判定为连接失败且本地该粒度有缓存,则**降级返回缓存而不是抛错**,并在响应头回写 `X-Dq-Cache-Fallback: true`(编排在 `MetadataService` 内的 `CacheFallback`,按请求线程存放标志,非连接类异常不降级以免掩盖真实错误)。无缓存可兜才原样抛出(HTTP 502/409)。**ER 关系推导**同样按此口径降级(未就绪回源取整库字段清单失败→读 `meta_schema_column` 缓存继续推导,候选标「未验证」,见 ER关系推导.md),但它跑在异步任务线程、要调整的是任务进度与附注而非响应头,因此降级编排写在 `RelationInferService` 内(复用同一套 `ConnectionFailureClassifier` 判定与数据源标记口径)。缓存落库:`meta_table`/`meta_column`/`meta_index`/`meta_schema_column`/`meta_database`(V10/V27/V29)+ `schema_stat`,以及 V40 新增的 `meta_ddl`(单表建表 DDL 整粒度)与 `meta_column_count`(schema 字段总数,0 是合法值,行存在即就绪);后两者无 flag,由 `replaceTables`/`replaceColumns`/`replaceIndexes`/`replaceSchemaColumns` 在结构覆盖刷新时按粒度失效(表/字段/索引变了,DDL 与字段总数不再可信)。**源库文本列一律放宽为 CLOB**(V42:`meta_column.display_type/default_value/comment`、`meta_schema_column.col_type/comment`、`meta_table.comment`,以及扫描快照的 `scan_column.column_type/column_comment/default_value`、`scan_table.comment`)——方言给出的类型定义与注释不受本地列宽约束:MySQL 的 `COLUMN_TYPE` 对 ENUM/SET 会带出完整枚举列表(几十个枚举值即超原 VARCHAR(128)),PG/Oracle 的注释与默认值同样没有实际上限,原列宽会让**整批**缓存刷新或扫描写入因 22001 失败;这里选择放宽列类型而不是截断,保证缓存/快照与源库一致(名称类列受各库标识符上限约束,仍是 VARCHAR(256))。仅「新建/续扫」「数据预览」「SQL 控制台」等需要真实取数的操作断网必失败(前端各自有内联错误/catch 兜底);**已有扫描记录的查看与导出全在本地 H2**(`scan_job`/`scan_table`/`scan_chunk`/字段统计明细,`ScanService.listJobs`/`getJob`/`getColumns` 与 `ExportService`/`ScanWordExportService` 均不连业务库),Word 数据调研报告导出的体积实时补算失败会 catch 后按未知体积继续,不中断导出。**效果**:用户更换网络环境(如从内网切到外网/VPN 断开)后,此前浏览过的库、表结构、单表 DDL 与全部历史扫描结果仍可正常查看,库列表/表列表页顶部与字段明细 DDL 视图显示「数据源当前不可达,正在展示本地缓存」,点「刷新」也不再报红错而是提示已保留本地缓存;恢复网络后刷新即重新同步。**缓存写入路径**共四条:① 浏览懒加载(首次访问某粒度回源并落库);② 库/表/字段明细页「刷新」强制回源(`?refresh=true`);③ 发起扫描顺带刷新(`createScan` 刷表清单、`planTable` 刷字段+索引,失败不影响扫描);④ 数据源页「刷新」的元数据批量同步(见下节 —— 复用同一组 `MetadataService` refresh 方法做整粒度预取,缓存体系本身未改,只是新增一条批量写入路径)

## 元数据批量同步(数据源页「刷新」按钮)

数据源列表页工具栏「刷新」按钮(前端 `MetadataSyncDialog.vue`)把选中的数据源(**默认全选**;连接异常的行带红字提示但仍可勾选)的全部结构元数据一次性回源并覆盖进本地 H2 缓存,同步成功后断网也能浏览这些库表结构。

- **同步范围**:逐数据源 实测连接 → 库清单(`meta_database`)→ schema 清单 → 表清单(`meta_table`)→ 整库 lite 字段清单(`meta_schema_column`)→ 逐表详细字段(`meta_column`)+ 索引(`meta_index`)→ schema 字段总数(`meta_column_count`)→ 库概览(`schema_stat`);覆盖为整粒度更新(先 DELETE 后 INSERT,同 `MetaCacheRepository` 条纹锁串行化),已有缓存被最新覆盖。缓存存全量、不按库过滤白名单裁剪(与懒加载口径一致,白名单在读取路径过滤)。**DDL 不同步**:Oracle/达梦逐表取建表 DDL 太慢,维持按需浏览 + 缓存降级现状
- **任务模型**(`MetaSyncService`,common):任务落 H2 `meta_sync_job`/`meta_sync_item`(V41),复用 `SampleExportService` 那套「任务落库 + 守护线程池 + 前端轮询」范式 —— 4 线程守护池执行,同一时刻只允许一个 RUNNING 任务,重复提交 409;每数据源先 `getConnection` 实测连接判成败(浏览接口有缓存时会降级返回而不抛错,不能以 refresh 调用是否抛异常判成败),连不上则该项记 FAILED 并写数据源 `conn_status/conn_kind` 标记(分类同 `ConnectionFailureClassifier`),**不中断整批**;同步中途断连被 `CacheFallback` 降级读了旧缓存时也判该数据源失败,不拿陈旧缓存当成果;支持取消(逐表/逐数据源检查点响应);服务重启把残留 PENDING/RUNNING 任务与明细置 FAILED(`recoverUnfinished`)
- **端点**:`POST /api/metadata-sync`(body `{"datasourceIds":[...]}`,空列表 400 / 已有运行中任务 409,返回 `jobId`)、`GET /api/metadata-sync/latest`(页面打开恢复轮询,从未同步过返回 204)、`GET /api/metadata-sync/{id}`(进度轮询)、`POST /api/metadata-sync/{id}/cancel`
- **前端**:`MetadataSyncDialog.vue` 选择视图(勾选数据源)+ 进度视图(1s 轮询,可取消 / 后台运行),任务终态后回调数据源页刷新列表(连接状态标记可能变化)

- 与②库/表/字段明细页「刷新」的区别:页面级「刷新」是进入某页后按当前粒度强制回源,覆盖当前可见范围;本功能是后台**整库预取**,一次覆盖多个数据源的全部粒度,把「先访问再缓存」变成「提前铺缓存」,便于换网络/断网后离线浏览。与③的关系:二者都调用 `MetadataService` 的覆盖刷新,差别只在触发方(扫描流程 vs 独立后台任务)与范围
