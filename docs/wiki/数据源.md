# 数据源

> dq-tool 项目文档,索引见根 [AGENTS.md](../../AGENTS.md)。本文覆盖数据源存储加密、SSH 隧道、库过滤、分组、导入导出。

- 数据源连接信息存本地 H2 文件库,密码 AES-GCM 加密
- 业务库连接池(`DataSourceService.pools`,HikariCP):key 为 `数据源id|库名` —— 多库方言(SQL Server/Kingbase)按解析后的目标库**按库分池**,同一物理连接固定一个库,`getConnection(datasourceId, database)` 借出时已切好 catalog(调用方不再自行 `useDatabase`);如此规避 mssql-jdbc 的 `DatabaseMetaData` 缓存语句句柄在 `USE` 跨库后失效不可恢复的坑(错误 586/8179「prepared statement handle is not valid in this context」,驱动默认语句池关闭时不会自动重试);Kingbase 走 PG 协议无法切库,分池 URL 由 `DbDialect.jdbcUrlForDatabase` 改写路径段指向目标库;非多库方言 database 参数忽略,单池。`evictPool` 按 `id|` 前缀回收该数据源全部分池并关闭 SSH 隧道
- Kingbase 多库:`supportsMultiDatabase()=true`,先选库再选 schema(与 SQL Server 同一套跨库浏览/扫描链路);`listDatabases` 查 `pg_database`(排除模板库与禁止连接的库);JDBC URL 未指定库时驱动按用户名当库名导致连接失败,`connectionUrlCandidates` 按序回落维护库候选(原样 → kingbase → test → template1,首个连通者胜),测试连接/库过滤预览/模式探测/默认池建池统一走该回落;库过滤白名单作用层级随之变为数据库级,存量 Kingbase 数据源的 schema 级旧白名单由 V23 迁移清空(旧值在新口径下匹配不到任何数据库)
- SQL Server 版本探测:`SqlServerDialect.detectDbMode` 查 `SERVERPROPERTY('ProductVersion')` 并按主版本号映射营销版本(如 "2014 (12.0.5000.0)"),复用金仓 detectDbMode 同一通道 —— 连通性实测(排错中心显示「SQL Server 2014 (...)」、诊断报告标「版本」)与数据源保存时落 `data_source.db_mode`;方言行为的版本分支(分页语法等)仍以 `sqlServerMajor(conn)` 实时探测为准,不读该缓存值
- 数据源分组:`data_source.group_name` 自由文本列(空=未分组),不设独立分组表,分组列表由前端从现有数据源聚合去重;编辑对话框「常规」页签可输入新分组或选已有分组(el-select allow-create),数据源页按分组渲染可折叠区块(命名分组按名称排序、未分组排最后、组内保持收藏置顶,全库无分组时退化为平铺网格),可按分组筛选/搜索;卡片可拖拽到其他分组区块(分组头或卡片网格均可放置,拖到「未分组」即移出分组)直接改分组,走轻量接口 `PUT /api/datasources/{id}/group`(`{"groupName": "xxx"}`,null/空白=未分组;只动 group_name 一列,不走全量 PUT 的连库探测);侧边栏数据源菜单同样按分组成组(命名分组为可折叠子菜单、下钻时自动展开所在分组,未分组平铺在最后);分组随导出/导入 JSON 一并迁移(Navicat/DataGrip 导入无分组概念,落为未分组)
- 数据源 SSH 隧道:可配置经跳板机连接目标库(password/publickey 认证,私钥内容入库非文件路径;三个 SSH 秘密字段同样 AES-GCM 加密、编辑留空不改),内核 `SshTunnelService`(SSHJ 本地端口转发)+ `JdbcUrlRewriter`(JDBC URL host:port 解析/改写为 127.0.0.1:转发端口);连接池用长驻隧道(evictPool 一并关闭),测试连接/保存前模式探测用一次性隧道
- 数据源库过滤:数据源级库白名单(`data_source.schema_filter` 逗号分隔,空=不过滤),编辑对话框「库过滤」页签(DataGrip Schemas 页风格)拉取目标库库名勾选 —— 编辑态且连接信息未改(前端快照对比,改过连接字段即失效已拉列表)直接调已存数据源的 `databases`/`schemas` 接口(带 `all=true` 旁路白名单拿全量,切到该页签自动加载);新增态或编辑态改过连接信息时用 `POST /api/datasources/preview-databases` 按表单连接参数实时连接(请求带 id 时密码/SSH 秘密留空回落已存值;方言 `listDatabases` 为空时回落 `listSchemas`,因为只有 SQL Server/Kingbase 实现了多库列表);白名单作用层级按方言能力区分 —— 多库方言(`DbDialect.supportsMultiDatabase()`,SQL Server/Kingbase)只过滤 `GET /api/datasources/{dsId}/databases`,单库方言(MySQL 等的 schema 即用户眼中的库)过滤 `listSchemas` 与 schema-stats 概览(写入与读取路径都过滤,旧缓存无需重建;MetadataService.applySchemaFilter);库列表页也有「库过滤」弹窗直接改白名单(`PUT /api/datasources/{id}/schema-filter` 单独更新该列,DataSourceService.updateSchemaFilter);系统库不参与业务扫描,各方言在 `DbDialect.systemSchemas()` 给出小写系统库名集合(多库方言为数据库级:SQL Server 的 master/model/msdb/tempdb + SSRS 的 ReportServer 两个组件库、Kingbase 的 kingbase/test/security/template0/1;单库方言为 schema 级:MySQL 四件套、Oracle/DM 内置账号 schema 等),经 `GET /api/db-types/{dbType}/system-schemas` 静态下发(不连业务库),库过滤页签与弹窗拉列表时并行拉取——未配置白名单时系统库默认不勾选并打「系统」灰标(比对大小写不敏感),已配置白名单时按已存配置回填;白名单随导出/导入 JSON 一并迁移
- 数据源导入/导出:数据源页可勾选导出为 JSON(密码与 SSH 秘密字段用内置固定口令 TransferCrypto 重加密,跨实例可导入,仅防随手打开),导入支持本工具 JSON 与 Navicat .ncx(NavicatCrypto 解 Ver 1.x AES-128-CBC 密码;SSH 隧道配置随数据源一并导入,SSH_PrivateKey 只是用户机器上的文件路径读不到内容,非空时提示导入后手动粘贴私钥),重名自动加「 (2)」后缀不覆盖;导入对话框分「文件导入/粘贴导入」两模式,粘贴模式支持 DataGrip「复制数据源到剪贴板」的 XML(带 `#DataSourceSettings#`/`#BEGIN#` 注释行包裹,密码在 IDE 主密码保险箱拿不到,导入后提示逐个编辑补密码)与本工具 JSON 文本,服务端按内容自动识别;逻辑在内核 `DataSourceTransferService`,接口 `GET /api/datasources/export?ids=`、`POST /api/datasources/import`(multipart,文件字段 `file` 或文本字段 `text`);导入的无密码数据源(DataGrip 导入必然无密码、Navicat .ncx 未保存密码、JSON `passwordEnc` 为空时导入成功并带 warning)在数据源卡片上以「未设密码」标出 —— 列表接口从 `password_enc` 判空返回 `hasPassword`(新建密码必填、编辑留空沿用旧值,故无歧义状态,无需持久化列)
