# 元数据导入导出

> 数据源页「刷新」把结构元数据同步进本地 H2 缓存(见 [数据源](数据源.md) 的元数据批量同步)。
> 本功能把**某数据源的元数据缓存连同派生标注数据打包成 JSON 文件**,交给连不上业务库的人导入,
> 导入后即可离线使用 ER 关系、图谱、对象管理、表列表、表说明、表标记等功能。

## 使用场景

人员角色不同、分工不同:不是所有人都能直连数据源。现场人员刷新一次元数据缓存后,
把元数据导出发给其他人员;其他人导入后即可使用依赖元数据的功能,无需网络可达业务库。

- 导出入口:数据源页工具栏「导出元数据」(与「导出配置(JSON)」共用勾选弹窗,弹窗内可切换导出内容)
- 导入入口:数据源页「导入配置」(与连接配置同一个弹窗,文件按顶层 `app` 字段自动识别分发)
- 后端:`GET /api/datasources/metadata-export?ids=`、`POST /api/datasources/import`(JSON 按 app 分发)

## 导出范围

每个数据源一个 item(`app=dq-tool-metadata`,`version=1`):

| 数据段 | 内容 | 导入语义 |
|---|---|---|
| datasource | 连接配置(密码 TransferCrypto 固定密钥加密,与数据源导出同一口径) | 按名称匹配本机数据源;匹配不到才新建 |
| 结构缓存 9 表 | meta_database / meta_table / meta_column / meta_index / meta_schema_column / meta_ddl / meta_column_count / meta_cache_flag / schema_stat | **整粒度替换**(与「刷新」的 delete+insert 同口径,缓存语义) |
| table_doc / schema_doc | 表说明(含 model)、库级描述 | upsert 覆盖 |
| tag_def + table_tag | 被引用的 USER 标记定义 + 表标记关系(系统空表标记不迁移) | 标记按 name 合并;打标 MERGE 幂等,保留打标来源 |
| table_system / manual_collect | 表所属系统、人工采集收藏 | upsert / insert-if-absent |
| table_relation | ER 关系(候选/确认/否决三态) | insert-if-absent:**不覆盖本机已有的否决/确认决策** |
| object_dir / object_table / object_table_rel | 对象管理目录树、挂载表、登记的关系表 | 目录按 (parent_id, name) 逐级匹配/新建做 **id 重映射**;挂载/关系按重映射后 id 幂等补齐 |

不导出:`scan_*`(扫描记录有独立 Transfer)、`relation_infer_job` / `meta_sync_*`(纯历史任务)。

## 文件格式:行袋(row-map)

各数据段是「行袋」:`[{"列名": 值, ...}]`,键与本地 H2 表列名一致(snake_case),时间列统一为
ISO_LOCAL_DATE_TIME 字符串。兼容策略(铁律见 [代码约定与安全](代码约定与安全.md)):

- **前向兼容**(新文件进旧软件):导入端按目标表实际列(INFORMATION_SCHEMA)过滤行内多余键,未知列忽略;
- **后向兼容**(旧文件进新软件):同版本内新增段/新增键靠可空列与默认值兜底;
- 缺 NOT NULL 无默认值关键列的坏行在插入前过滤(不拖垮整表),跳过行数计入导入警告;
- 破坏性变更才升 `version` 并分版本解析。

维护约定:**新增结构缓存表时**需把表名登记到 `MetadataTransferService.importOne` 的段清单,
且新增列必须可空或有默认值(否则旧文件导入会被当坏行过滤)。

## 导入语义要点

- 数据源定位:**导入前预检映射**(`POST /api/datasources/metadata-transfer/preview`,文件/粘贴文本均可)——
  按**连接身份**(`type|host小写|port|username|database`,与表格批量导入去重同口径,见 `SampleTableExcelParser.dsKey`)
  自动匹配本机数据源并预填,用户可改选任意本机数据源或「新建数据源」;`mapping` 表单字段回传
  (文件数据源名 → 本机 id,**缺失=自动匹配,0=强制新建,>0=指定本机数据源**);
  匹配命中时本机连接配置与名称均不被文件覆盖(数据源改名不影响身份匹配);新建时无密码照常建源
  (列表以「未设密码」标出并提示补充),重名自动加「 (2)」后缀。
- 结构缓存是**替换**语义(快照接管);派生数据是**合并**语义(幂等,重复导入不产生重复行,
  不覆盖本机决策)。想把派生数据也刷新成文件口径:删除本机该数据源后重新导入。
- 数据源正在跑元数据同步时拒绝导入该条(避免与同步的整粒度覆盖互相踩踏)。
- 行内 `datasource_id` 一律强制改写为目标数据源 id,文件里的值不作数。
- 失败留痕:每个数据源的导入失败除计入导入结果外,带堆栈落 error 日志;跳过的坏行按表记 warn 日志(数量 + 首行缺失的必填列)。

## 离线可用边界

导入后即可纯本地工作的功能:库/表/字段/索引/DDL 浏览、ER 关系推导(名字通道+语义通道,
值交集验证自动降级为「未验证候选」)、ER 图/星型图、对象管理与图谱、表说明查看与编辑、
表标记/所属系统/人工采集管理、表结构 Word 导出。

仍需连业务库的:发起/续扫、数据预览、SQL 控制台(业务库)、AI 生成表说明、抽样导出、元数据「刷新」
(连不上时按降级口径返回本地缓存并提示)。
